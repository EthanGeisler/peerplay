# 8.3 — Server: Relay protocol — listing metadata API

## What was done

Added four new relay API endpoints in `server/packages/relay/src/routes.ts` for listing metadata exchange between relays and sovereign clients.

### New endpoints

1. **GET /api/relay/listings** — Public listing feed for relay consumers
   - Returns published listings with creator pubkey and signature
   - Supports `?contentType=GAME` filter (validated against ContentType enum)
   - Supports `?creator=<pubkey>` filter (64-char hex pubkey)
   - Supports `?limit=50&offset=0` pagination (clamped 1-100)
   - Response: `{ listings: [...], total: number }`

2. **GET /api/relay/listings/:id** — Single listing detail
   - Returns full listing data including versions (READY only) and studioName
   - 404 if not found or not PUBLISHED

3. **GET /api/relay/creators** — List unique creators (developers with pubkeys)
   - Queries developers whose users have `nostrPubkey` set
   - Returns: `{ creators: [{ pubkey, displayName, listingCount }] }`
   - `listingCount` counts only PUBLISHED listings

4. **POST /api/relay/listings** — Submit a signed listing (federation/sovereign clients)
   - Requires: `{ listing: { title, slug, ... }, signature, creatorPublicKey }`
   - Verifies Schnorr signature over canonical data: `JSON.stringify({ title, slug, description, priceCents, contentType })`
   - SHA-256 hash of canonical JSON, verified with `@noble/curves` schnorr
   - Rejects with 400 if signature is invalid
   - Stores as `FederatedListing` (upsert by relayUrl + remoteId)
   - Response: `{ success: true, id: "..." }`

### Implementation details

- All routes added to the existing `relayRouter` in `server/packages/relay/src/routes.ts`
- Uses existing `db.listing.*` for local listings, `db.federatedListing.*` for federated submissions
- Uses `@noble/curves/secp256k1.js` schnorr (already imported) for signature verification
- Only PUBLISHED listings appear in relay feeds
- No authentication required for GET endpoints (public relay data)
- POST endpoint is unauthenticated (federation protocol — signature provides authentication)
