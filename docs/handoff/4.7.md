## Key decisions made during implementation

- **Profile fallback when no kind 0 event exists.** If `GET /api/profiles/:pubkey` returns 404, the page still renders with just the pubkey (truncated as display name) and placeholder avatar. This is important because users who haven't set a profile yet should still have a viewable profile page.

- **Review count via events query.** Used `GET /api/events?kinds=31337&authors=PUBKEY` and counted the array length client-side. This is simple and sufficient — the count is bounded by the number of games the user has reviewed.

- **Follow state check.** The page fetches the current user's follow list via `GET /api/follows/:currentUserPubkey` and checks if the viewed pubkey is in the list. This reuses the existing 4.6 endpoint without needing a dedicated "am I following this user?" API.

- **Styling consistency.** Web version uses CSS variables (`var(--bg-secondary)`, etc.) matching the existing web storefront. Client version uses hardcoded hex colors (`#16213e`, `#e94560`, etc.) matching the existing Electron client styling pattern.

- **Profile links from reviews.** Updated both web and client ReviewSection components to make the author pubkey clickable, navigating to `/profile/:pubkey`. Web uses `<Link>`, client uses `useNavigate` with a click handler.

## How it works

### Profile page displays:
1. **Avatar** — from kind 0 event `picture` field, fallback to placeholder
2. **Display name** — from kind 0 event `name` field, fallback to truncated pubkey
3. **Full pubkey** — shown in monospace below the name
4. **Bio/about** — from kind 0 event `about` field, hidden if empty
5. **Member since** — from the kind 0 event's `created_at` timestamp
6. **Review count** — queried from events endpoint (kind 31337 by author)
7. **Follow/Unfollow button** — only shown when logged in and viewing someone else's profile
8. **Seeder Reputation placeholder** — "Seeder Score: Coming Soon" section for Phase 5

### API calls made:
- `GET /api/profiles/:pubkey` — profile data (name, about, picture, created_at)
- `GET /api/events?kinds=31337&authors=:pubkey` — review events for count
- `GET /api/follows/:currentUserPubkey` — current user's follow list (for button state)
- `POST /api/follows` — follow action
- `DELETE /api/follows/:pubkey` — unfollow action

### Navigation to profiles:
- Review cards in both web and client now have clickable pubkeys that navigate to the author's profile page
