# 8.12 — App Distribution via BitTorrent

## What was done

### 1. Created `scripts/create-installer-torrent.mjs`

A standalone script that generates a `.torrent` file for the BoilerDeck desktop client installer.

**Usage:**
```bash
node scripts/create-installer-torrent.mjs <path-to-installer> [--output <dir>]
node scripts/create-installer-torrent.mjs --help
```

**Example:**
```bash
node scripts/create-installer-torrent.mjs "client/release/BoilerDeck Setup 0.3.1.exe"
node scripts/create-installer-torrent.mjs "client/release/BoilerDeck-0.3.1.AppImage" --output dist/
```

**Features:**
- Accepts `.exe` or `.AppImage` installer paths (warns on other extensions but continues)
- Uses `create-torrent` (already a project dependency) with three public trackers
- Sets comment to `"BoilerDeck Desktop Client - https://boilerdeck.com"`
- Piece length auto-determined by `create-torrent` based on file size
- Outputs `.torrent` file next to the input file (or custom dir via `--output`)
- Prints info hash and magnet URI on success
- `--help` flag prints usage

**Trackers:**
- `udp://tracker.opentrackr.org:1337/announce`
- `udp://open.stealth.si:80/announce`
- `udp://tracker.torrent.eu.org:451/announce`

### 2. Documented APP_UPDATE listing type concept

Added a "Future: APP_UPDATE Content Type" section to the end of `docs/relay-guide.md` describing:
- The concept: publish client updates as relay events with torrent info hashes
- Flow: developer builds release, generates torrent, publishes APP_UPDATE event, clients subscribe and prompt to update
- Benefits: decentralized distribution, censorship resistance, integrity verification, bandwidth sharing
- Draft event structure (kind 31339, parameterized replaceable)
- Clearly marked as a concept/placeholder, not implemented
