## Key decisions made during implementation

- **Badge system uses colored styled labels, not emoji.** Bronze (#cd7f32), Silver (#c0c0c0), Gold (#ffd700) with matching semi-transparent backgrounds and borders. Follows the spec's preference for styled labels over emoji.

- **Top Seeders queries all kind 31338 events then filters client-side.** There's no dedicated "top seeders for game X" endpoint. The component fetches all attestation events, filters by game slug in tags (`game` tag or `d` tag containing slug), extracts unique seeder pubkeys from `p` tags, then fetches reputation for each. This is bounded since attestations are parameterized replaceable.

- **Top Seeders limited to 10.** Sorted by score descending, capped at 10 entries for display.

- **Score formatted to 1 decimal place** as specified (`.toFixed(1)`).

## How it works

### Profile page reputation display
1. On mount, fetches `GET /api/reputation/:pubkey`
2. If `score > 0`: shows score (28px bold), "Seeder Score" label, badge (if score >= 10), attestation count, unique attesters
3. If `score === 0` or fetch fails: shows "No seeding activity yet"
4. Badge thresholds: Bronze (>= 10), Silver (>= 50), Gold (>= 200)

### Game detail Top Seeders section
1. Fetches `GET /api/events?kinds=31338` (all attestation events)
2. Filters events by game slug in `game` tag or `d` tag
3. Extracts unique seeder pubkeys from `p` tags
4. Fetches `GET /api/reputation/:pubkey` for each seeder
5. Sorts by score descending, shows top 10
6. Each row: rank, truncated pubkey (links to profile), score, badge
7. If no seeders: shows placeholder message about data accumulating
