## Key decisions made during implementation
- **Combined outbound + inbound in one file.** Both share connection management, reconnect logic, and the imported event tracking set. Splitting into two files would duplicate the connection state.
- **`importedEventIds` Set for loop prevention.** Tracks event IDs received from federation. These are never re-forwarded outbound. Pruned at 10k entries (removes oldest half).
- **Subscribe to game-related kinds on connect.** Inbound subscriptions request kinds 30001, 30002, 31337, 31338 (listings, versions, reviews, attestations). This is a broad filter — future refinement can filter by local game slug `d` tags.
- **`EXTERNAL_RELAYS` env var.** Comma-separated list of WebSocket URLs. Empty or absent = federation disabled.

## How it works

### Outbound flow
1. Event is published locally (via WS, REST POST /events, or sign-and-publish)
2. After storing and fan-out, `federateOutbound(event)` is called
3. `federateOutbound` checks `importedEventIds` — skips if event was imported (loop prevention)
4. Sends `["EVENT", event]` to all connected external relays

### Inbound flow
1. On connect to external relay, sends `["REQ", "federation-inbound", { kinds: [30001, 30002, 31337, 31338] }]`
2. External relay pushes matching events
3. Each event is validated (shape + signature verification)
4. `markImported(event.id)` is called before storing (loop prevention)
5. Event is stored locally and fanned out to local WS subscribers

### Auto-reconnect
Same exponential backoff pattern as the client relay manager: 1s, 2s, 4s, ..., max 30s.
