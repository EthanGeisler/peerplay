# Sub-task 4.9 — Moderation: Mute and Report

## What was built
- **`server/packages/relay/src/routes.ts`** (MODIFIED) — Added four moderation endpoints:
  - `POST /api/moderation/mute` — mute a pubkey (authenticated)
  - `DELETE /api/moderation/mute/:pubkey` — unmute a pubkey (authenticated)
  - `GET /api/moderation/mute` — get current mute list (authenticated)
  - `POST /api/moderation/delete` — admin event deletion via kind 5 (authenticated, ADMIN only)
- **`server/packages/relay/src/ws.ts`** (MODIFIED) — `fanOutEvent` now checks Redis mute lists before delivering events to subscribers; added `setConnectionUser()` and `getConnectionIds()` exports
- **`server/packages/relay/src/index.ts`** (MODIFIED) — Added barrel exports for `setConnectionUser` and `getConnectionIds`
- **`server/packages/shared/src/config.ts`** (MODIFIED) — Added `RELAY_ADMIN_PRIVKEY` optional env var

## Key decisions made during implementation

- **Redis sets for mute lists.** Mute lists stored as Redis sets keyed by `mute_list:{userId}`. Fast O(1) membership checks via `SISMEMBER`, no schema migration needed, and Redis sets naturally deduplicate.

- **Mute filtering in `fanOutEvent`.** Changed `fanOutEvent` from sync to async. For each WS connection with a known `userId`, it checks `redis.sismember()` before delivering events. Connections without a userId (anonymous WS connections) receive all events unfiltered.

- **Connection-user association.** Added `userId` field to `ConnectionState` and `setConnectionUser(connId, userId)` function. This allows authenticated REST paths or future NIP-42 AUTH to associate a WS connection with a user for mute filtering.

- **Admin deletion via relay keypair.** Admin deletion creates a kind 5 event signed by the relay's own keypair (`RELAY_ADMIN_PRIVKEY` env var). The target event is deleted from DB, and the kind 5 event is stored, fanned out, and federated outbound. If `RELAY_ADMIN_PRIVKEY` is not set, the endpoint returns 503.

- **Non-existent pubkey muting.** Muting a non-existent pubkey succeeds silently (stored in Redis). This supports federation use cases where a user may not be in the local DB.

## How it works

### Mute flow
1. Authenticated user calls `POST /api/moderation/mute` with `{ pubkey: "64-char-hex" }`
2. Server validates pubkey format, checks it's not a self-mute (400 if so)
3. Adds pubkey to Redis set `mute_list:{userId}`
4. Returns `{ muted: ["pubkey1", "pubkey2", ...] }`

### Mute filtering in WS
1. When `fanOutEvent(event)` runs, for each connection with a `userId`:
   - Calls `redis.sismember("mute_list:{userId}", event.pubkey)`
   - If muted, skips the entire connection (no events from that author)
2. Connections without `userId` receive all events (no filtering)

### Unmute flow
1. `DELETE /api/moderation/mute/:pubkey` removes the pubkey from Redis set
2. Future events from that pubkey immediately start appearing in subscriptions

### Admin deletion flow
1. Admin calls `POST /api/moderation/delete` with `{ eventId: "64-char-hex" }`
2. Server verifies `RELAY_ADMIN_PRIVKEY` is configured (503 if not)
3. Verifies target event exists (404 if not)
4. Derives admin pubkey from `RELAY_ADMIN_PRIVKEY`
5. Creates a kind 5 deletion event with `["e", targetEventId]` tag, signed by relay admin keypair
6. Deletes target event from DB via `deleteEvent()`
7. Stores the kind 5 event
8. Fans out kind 5 to WS subscribers
9. Federates kind 5 outbound to external relays

### Key function signatures
```typescript
// Mute list operations (Redis sets)
redis.sadd(`mute_list:${userId}`, pubkey)    // mute
redis.srem(`mute_list:${userId}`, pubkey)    // unmute
redis.sismember(`mute_list:${userId}`, pubkey) // check
redis.smembers(`mute_list:${userId}`)        // list all

// WS connection user association
setConnectionUser(connId: string, userId: string): void

// Admin deletion
POST /api/moderation/delete { eventId: string } → { deleted, targetEventId, deletionEventId }
```

## Gotchas and surprises

- **`fanOutEvent` is now async.** All callers in routes.ts, ws.ts, and federation.ts were updated to `await` it. This was necessary for the Redis mute check but changes the function signature from `void` to `Promise<void>`.

- **WS connections don't authenticate by default.** The mute filtering only works for connections that have been associated with a user via `setConnectionUser()`. Anonymous WS connections receive all events. A future NIP-42 AUTH implementation could wire this up automatically.

- **RELAY_ADMIN_PRIVKEY must be set manually.** The admin deletion endpoint returns 503 if this env var is not configured. The operator must generate a keypair and set it. Generate one with:
  ```bash
  node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
  ```

## How to use / test

### Mute a pubkey
```bash
curl -X POST https://boilerdeck.com/api/moderation/mute \
  -H "Authorization: Bearer <access_token>" \
  -H "Content-Type: application/json" \
  -d '{"pubkey":"<64-char-hex-pubkey>"}'
```

### Get mute list
```bash
curl https://boilerdeck.com/api/moderation/mute \
  -H "Authorization: Bearer <access_token>"
```

### Unmute
```bash
curl -X DELETE https://boilerdeck.com/api/moderation/mute/<64-char-hex-pubkey> \
  -H "Authorization: Bearer <access_token>"
```

### Self-mute (should return 400)
```bash
curl -X POST https://boilerdeck.com/api/moderation/mute \
  -H "Authorization: Bearer <access_token>" \
  -H "Content-Type: application/json" \
  -d '{"pubkey":"<your-own-pubkey>"}'
```

### Admin delete event
```bash
curl -X POST https://boilerdeck.com/api/moderation/delete \
  -H "Authorization: Bearer <admin_access_token>" \
  -H "Content-Type: application/json" \
  -d '{"eventId":"<64-char-hex-event-id>"}'
```

## IMPORTANT: VPS Configuration Required

**`RELAY_ADMIN_PRIVKEY` must be set on the VPS before admin deletion will work.**

Add to `/opt/boilerdeck/server/.env`:
```
RELAY_ADMIN_PRIVKEY=<64-char-hex-private-key>
```

Generate a keypair:
```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

The corresponding pubkey can be derived from this private key — it will be used as the author of admin deletion events (kind 5).

## What the next sub-task needs to know
- **Mute lists are in Redis** as sets keyed by `mute_list:{userId}`. Any service that needs to check mutes can use `redis.sismember()`.
- **`fanOutEvent` is now async** — all callers must await it.
- **WS mute filtering requires `setConnectionUser()`** — if NIP-42 AUTH is implemented, call this to enable mute filtering for WS connections.
- **Admin deletion creates kind 5 events** signed by the relay admin keypair. External relays that receive these should honor them per NIP-09.
- **Phase 5 (reputation)** may want to check mute lists for weighting (muted = 0x weight, per 5.6 spec).
