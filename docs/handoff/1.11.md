# Sub-task 1.11 — Electron client: mnemonic flow

## What was built
- **`client/src/renderer/types.ts`** — added `mnemonic?: string` to `ApiAuthResponse`, `nostrPubkey?: string` to `ApiUser`
- **`client/src/renderer/stores/authStore.ts`** — `login()` and `register()` return types changed from `Promise<void>` to `Promise<string | undefined>`, both now return `data.mnemonic`
- **`client/src/renderer/components/MnemonicModal.tsx`** (NEW) — mnemonic display modal matching Electron's color scheme
- **`client/src/renderer/pages/Login.tsx`** — both login and register handlers capture mnemonic and show MnemonicModal; navigation deferred until modal is dismissed

## Key decisions made during implementation
- **New MnemonicModal component rather than sharing web's.** The Electron renderer uses hardcoded hex colors (`#e94560`, `#16213e`, `#0f3460`, `#1a1a2e`) while the web storefront uses CSS custom properties (`--bg-secondary`, `--accent`, etc.). A shared component would need a theming layer that doesn't exist yet. Simpler to create a matching component with the right colors.
- **Both login and register return mnemonic.** Unlike the web store which only added mnemonic return to `login()` in 1.10 (register already had it from 1.9), the Electron store needed both updated since neither returned it.
- **Unified handler for both tabs.** Both login and register use the same `let m` pattern with a single mnemonic check, rather than duplicating the modal logic.

## How it works

### Login/register flow with mnemonic
```
User submits form → login() or register() API call
  → API returns { user, accessToken, refreshToken, mnemonic? }
  → Tokens stored via IPC (window.boilerdeck.store.set), user set in store
  → mnemonic returned from store action
  → If mnemonic: set in local state → MnemonicModal renders
  → User saves phrase → checks checkbox → clicks "Continue"
  → mnemonic cleared → navigate("/")
  → If no mnemonic: navigate("/") immediately
```

### MnemonicModal features (identical to web, different colors)
- 12 words in a 3-column grid with numbered labels
- "Copy to Clipboard" button (2s "Copied!" feedback)
- Confirmation checkbox gates "Continue" button
- "I'll do this later" escape hatch with two-click warning

## Gotchas and surprises
- **Electron client `ApiUser.role` uses `"USER"` not `"PLAYER"`.** The type says `"USER" | "DEVELOPER" | "ADMIN"` while the server Prisma schema uses `PLAYER`. This mismatch predates Phase 1 — not introduced here.
- **No error wrapping in store.** Unlike the web store which catches errors and sets `state.error`, the Electron store lets errors propagate to the component. The Login.tsx component catches them in its own try/catch. This pattern is unchanged.

## How to test
- Build and run the Electron client in dev mode: `npm run dev:client`
- Register a new account → mnemonic modal should appear
- Login with a pre-migration user → mnemonic modal should appear
- Login with an existing keypair user → no modal, goes straight to store
