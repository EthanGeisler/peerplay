# Sub-task 2.3 — Event storage service

## What was built
- **`server/packages/shared/src/eventStore.ts`** (NEW) — stores, retrieves, and queries NIP-01 events with signature verification, duplicate detection, and replaceable event semantics
- **`server/packages/shared/src/index.ts`** — re-exports `storeEvent`, `getEvent`, `queryEvents` and types

## Key decisions made during implementation
- **Read-then-update for replaceables, not upsert.** Prisma's `upsert` with composite unique keys is awkward and doesn't let us cleanly compare `created_at` to decide which event wins. The read-then-update pattern makes the "newer wins" logic explicit and readable.
- **P2002 catch for concurrent inserts.** If two identical events or two replaceables arrive simultaneously, the unique constraint catches the race. The loser gets `DUPLICATE` — no crash, no data corruption.
- **Three return values.** `STORED`, `DUPLICATE`, and `REPLACED` let callers distinguish between all three outcomes. `REPLACED` is useful for logging/metrics.
- **Query limit capped at 500, default 100.** Prevents unbounded queries. `limit: 0` and `limit: -1` return empty arrays (not errors).
- **`since > until` returns empty.** No error thrown — just no results. This matches NIP-01 relay behavior.
- **dTag normalization done at storage time.** Uses `normalizeDTag()` from events.ts — replaceable kinds get `""` (never null), regular kinds get `null`. This prevents the PostgreSQL NULL uniqueness issue.

## How it works

### `storeEvent(event)`
1. Calls `verifyEvent()` — rejects if signature or ID is invalid
2. Computes `dTag` via `normalizeDTag()`
3. For replaceable kinds (30000-39999): checks existing event with same `pubkey+kind+dTag`
   - No existing → insert
   - Existing with same ID → DUPLICATE
   - Existing is newer or same age → DUPLICATE (keeps existing)
   - Existing is older → updates in place → REPLACED
4. For regular kinds: straight insert, P2002 = DUPLICATE

### `queryEvents(filter)`
- Filters: `kinds` (array), `authors` (array of pubkeys), `since`/`until` (Unix timestamps), `limit`
- Returns `SignedEvent[]` ordered by `created_at` descending (newest first)
- Limit capped at 500, defaults to 100

## Gotchas and surprises
- **Prisma logs P2002 as `prisma:error` even when caught.** This is cosmetic — the error is handled correctly, but the log output looks alarming. Consider suppressing `error` log level in production if this becomes noisy.
- **The `update` approach for replaceable events updates the primary key (`id`).** This works in PostgreSQL but could be surprising — the row's identity changes. This is correct because the new event has a different hash (different content/timestamp).

## How to use / test
```typescript
import { storeEvent, getEvent, queryEvents, createEvent } from "@boilerdeck/shared";

// Store
const result = await storeEvent(signedEvent); // "STORED" | "DUPLICATE" | "REPLACED"

// Get by ID
const event = await getEvent("64-char-hex-id");

// Query
const events = await queryEvents({
  kinds: [30001],
  authors: ["pubkey-hex"],
  since: 1710000000,
  limit: 50,
});
```

## What the next sub-task needs to know
- Sub-task 2.4 (signing service) creates events with `createEvent()` — it should call `storeEvent()` to persist them after signing.
- Sub-task 2.5-2.7 (wrapping game/version operations) should call `storeEvent()` after creating events for games, updates, and versions.
- Sub-task 2.8 (REST endpoints) should use `storeEvent()` for POST and `getEvent()`/`queryEvents()` for GET.
- The `SignedEvent` type uses `created_at` (NIP-01) while Prisma uses `createdAt`. The conversion is handled internally by `eventStore.ts`.
- `storeEvent` throws `ValidationError` for invalid events — callers should let this propagate to the error handler (which returns 400).
