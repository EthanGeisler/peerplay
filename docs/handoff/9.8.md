# 9.8 — Web Locker View (Read-Only)

## Summary

Built the web storefront's read-only Data Locker page. Authenticated users can view their locker entries, copy magnet links for torrent download, and get prompted to install the desktop client for uploads. No upload capability from the web — that requires the Electron client.

## What Changed

### New File: `web/src/stores/lockerStore.ts`

Zustand store for locker state:

**State:**
- `entries` (LockerEntry[]) — locker file entries from server
- `quota` ({ used, max } | null) — storage usage in bytes
- `isLoading`, `error`
- `viewMode` ('grid' | 'list'), `searchQuery`
- `sortField` ('name' | 'size' | 'date'), `sortDir` ('asc' | 'desc')

**Actions:**
- `fetchEntries()` — calls `GET /api/locker/entries` via shared `apiFetch`, unwraps `data.entries` with `Array.isArray()` guard
- `setViewMode`, `setSearchQuery`, `setSortField`, `setSortDir`
- `clearError()`

Follows the exact same pattern as `libraryStore.ts` — Zustand create, `apiFetch` from `../api`, `ApiError` instance check for 401.

### New File: `web/src/pages/LockerPage.tsx`

Single page component with all sub-components inline (matching web project pattern — components are only extracted when reused across pages).

**Layout:**
- Auth gate: redirects to sign-in if not authenticated (same pattern as Library.tsx)
- Upload banner at top: "Upload files from the BoilerDeck Desktop app" with download link
- Error banner with dismiss button
- Quota bar: horizontal progress bar with color coding (green < 70%, yellow 70-90%, red > 90%)
- Toolbar: search input, sort dropdown (name/size/date), sort direction toggle, list/grid view toggle
- File list (list view): rows with MIME type badge, filename, tags, size, date, Magnet + Download buttons
- File grid (grid view): cards with MIME icon, filename, meta, tags, action buttons
- Empty state: "Your Data Locker is empty" with desktop app download CTA
- Empty search state: "No files match your search"

**Per-entry actions:**
- "Magnet" button — copies `magnetUri` to clipboard, shows "Copied!" toast
- "Download" button — links to BoilerDeck Desktop installer (the desktop client handles actual torrent download)

**Inline components:**
- `QuotaBar` — storage usage progress bar
- `FileRow` — list view file entry
- `FileCard` — grid view file entry
- `LockerToolbar` — search, sort, view toggle controls

**MIME type icons:** Monospace text badges (`IMG`, `VID`, `AUD`, `TXT`, `PDF`, `ZIP`, `EXE`, `FILE`) with color coding — same approach as the Electron client's LockerFileCard.

### Modified: `web/src/App.tsx`

- Added `LockerPage` import
- Changed static `NAV_ITEMS` to dynamic: base items + auth-gated items + tail items
  - "Locker" nav item appears between "Social" and "About" only when user is authenticated
  - Uses `useMemo` keyed on `user` to avoid recalculating on every render
- Added `<Route path="/locker" element={<LockerPage />} />` to routes

## Styling Approach

All inline styles using CSS custom properties (same as every other web page):
- `var(--bg-card)`, `var(--bg-tertiary)`, `var(--bg-hover)`, `var(--bg-secondary)`
- `var(--border)`, `var(--radius)`, `var(--radius-lg)`
- `var(--text-primary)`, `var(--text-secondary)`, `var(--text-muted)`
- `var(--accent)`, `var(--accent-green)`

Mobile-responsive: search input flexes, grid uses `auto-fill` with `minmax(200px, 1fr)`, tags/size/date columns have `className` hooks for future CSS hiding on small screens.

## Key Design Decisions

- **Read-only by design:** The web storefront cannot upload files — that requires Electron for local file access and torrent creation. The page makes this clear with the upload banner and download prompts.

- **Magnet link copy:** Users with their own torrent client (qBittorrent, Transmission, etc.) can copy the magnet URI and download directly. This is the primary web action.

- **"Download" links to desktop installer:** Since the web can't efficiently run WebTorrent, the Download button links to the BoilerDeck Desktop installer. A future improvement could use `boilerdeck://` deep links to open specific entries in the desktop client.

- **Server response shape:** The `GET /api/locker/entries` endpoint returns `{ entries: LockerEntry[], quota: { used: number, max: number } }`. The store guards with `Array.isArray()` as per CLAUDE.md conventions.

- **No separate component files:** Inline components follow the web project's existing pattern. The `web/src/components/` directory only has components shared across multiple pages (PostCard, ComposeBox, etc.). LockerPage's sub-components are page-specific.
