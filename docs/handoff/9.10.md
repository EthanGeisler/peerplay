# 9.10 — VPS Seed Management & Cleanup

## Summary

Server-side management of locker torrents: seeding lifecycle, cleanup cron, content-addressed deduplication, seed attestation for locker files, and a public health check endpoint.

## What Changed

### 1. Config Additions: `server/packages/locker/src/config.ts`

Two new config values in `LockerConfig`:

- `LOCKER_RETENTION_DAYS` — days to keep deleted files before hard-delete (default: 30, env: `LOCKER_RETENTION_DAYS`)
- `LOCKER_MAX_STORAGE_GB` — total VPS allocation for locker in GB (default: 500, env: `LOCKER_MAX_STORAGE_GB`)

### 2. Seed Manager: `server/packages/locker/src/seedManager.ts`

New module with four exported functions:

- **`getLockerTorrentStats()`** — queries Transmission RPC for locker torrents (filtered by download directory containing `LOCKER_DIR`). Returns `{ active, paused, total, totalSize }`.
- **`pauseDeletedTorrents()`** — finds soft-deleted LockerFile records, cross-references with Transmission, pauses any active torrents for deleted entries. Returns count paused.
- **`removeExpiredTorrents(retentionDays)`** — finds LockerFile records deleted more than `retentionDays` ago, removes their torrents from Transmission. Returns count removed.
- **`getStorageStats()`** — returns `{ totalBytes, lockerBytes, availableBytes }`. Uses `fs.statfs` for disk stats and Prisma aggregate for locker bytes.

All functions use a shared `transmissionRpc()` helper that handles the CSRF session ID dance.

### 3. Deduplication: `server/packages/locker/src/dedup.ts`

Content-addressed dedup by SHA-256:

- **`findDuplicate(sha256)`** — queries DB for an existing non-deleted LockerFile with matching sha256. Returns the record or null.
- **`createSymlink(existingPath, newPath)`** — creates a symlink (or falls back to hard link, then copy on Windows/permission issues).

### 4. Upload Dedup Integration: `server/packages/locker/src/service.ts`

The `uploadFile()` function now:
1. Saves the file and computes SHA-256 (unchanged)
2. Calls `findDuplicate(sha256)` — if a match exists:
   - Reuses the existing torrent's `infoHash`
   - Reads the existing `.torrent` file and saves a copy in the new entry's directory
   - Skips `addToTransmission()` (existing torrent is already seeded)
   - Constructs `magnetUri` from the infoHash
3. If no duplicate, creates a new torrent as before
4. The `LockerFile` DB record now includes the `sha256` field

### 5. Prisma Schema Change

Added to `LockerFile` model:
- `sha256 String? @map("sha256")` — nullable (existing records won't have it)
- `@@index([sha256])` — for fast dedup lookups

Migration: `20260319055449_add_locker_sha256_index`

### 6. Cleanup Cron: `scripts/locker-cleanup-cron.ts`

Standalone script, runnable as `npx tsx scripts/locker-cleanup-cron.ts`. Tasks:

1. **Expired entries** — finds LockerFile records with `deletedAt` older than `LOCKER_RETENTION_DAYS`. Removes their torrents from Transmission, deletes files from disk (`fs.rm` recursive), hard-deletes DB records.
2. **Orphaned directories** — scans `LOCKER_DIR` for entry directories with no matching DB record. Removes them. Also cleans up empty user directories.
3. **Storage stats** — logs total active files, soft-deleted count, per-user breakdown (top 10), and disk space usage.

Error handling is non-fatal per-item (one failed cleanup doesn't stop others). Transmission being unreachable is logged but cleanup continues.

### 7. Seed Attestation Extension: `scripts/seed-attestation-cron.ts`

Updated to handle both marketplace and locker torrents:

- Transmission query now requests `downloadDir` field
- New `isLockerTorrent(torrent)` function checks if download directory contains `LOCKER_DIR`
- New `getLockerOwnerPubkeyForTorrent(infoHash)` function looks up pubkey via `LockerFile -> User -> nostrPubkey`
- Main loop now detects torrent type and uses the appropriate pubkey lookup
- Log output includes `[marketplace]` or `[locker]` tag for clarity
- All existing marketplace attestation logic is preserved

### 8. Health Endpoint: `GET /api/locker/health`

Public (no auth required). Returns:

```json
{
  "status": "ok" | "degraded",
  "transmission": {
    "connected": true,
    "activeTorrents": 5,
    "pausedTorrents": 1,
    "totalTorrents": 6,
    "totalTorrentSizeBytes": 1073741824
  },
  "storage": {
    "lockerUsedBytes": 524288000,
    "diskTotalBytes": 536870912000,
    "diskAvailableBytes": 214748364800
  }
}
```

Status is "degraded" when Transmission is unreachable. No sensitive data (no user IDs, no file paths).
