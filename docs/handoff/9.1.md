# 9.1 — Locker Event Schema & Types

## Summary

Defined the Nostr event kind and TypeScript types for data locker entries. Added kind constant `30078` (NIP-78 application-specific data) and created a new `locker.ts` module with the `LockerEntry` interface, serialization/deserialization helpers, validation, and Nostr event tag builder. Full unit test coverage with 37 passing tests.

## What Changed

### Shared: Kind Constants (`server/packages/shared/src/events.ts`)
- Added `EVENT_KIND_LOCKER_ENTRY = 30078` to the kind constants block

### Shared: Locker Module (`server/packages/shared/src/locker.ts`) — NEW
- `LOCKER_ENTRY_KIND = 30078` constant (also available as `EVENT_KIND_LOCKER_ENTRY` from events.ts)
- `LockerEntry` interface with all required fields:
  - `id` (UUID), `filename`, `size` (bytes), `mimeType`, `sha256` (64-char hex), `infoHash` (40-char hex), `magnetUri`, `createdAt` (unix timestamp), `tags` (string array), `version` (>= 1)
- `validateLockerEntry(entry: unknown): entry is LockerEntry` — type guard with full constraint checking (UUID format, hex lengths, magnet prefix, safe integers, non-empty strings, array element types)
- `serializeLockerEntry(entry: LockerEntry): string` — JSON.stringify wrapper
- `deserializeLockerEntry(json: string): LockerEntry` — JSON.parse + validation, throws on invalid input
- `buildLockerEventTags(entry: LockerEntry): string[][]` — returns `["d", id]` plus `["t", tag]` for each user tag

### Shared: Barrel Export (`server/packages/shared/src/index.ts`)
- Added `EVENT_KIND_LOCKER_ENTRY` to events.ts re-exports
- Added all locker.ts exports: `LOCKER_ENTRY_KIND`, `serializeLockerEntry`, `deserializeLockerEntry`, `validateLockerEntry`, `buildLockerEventTags`, and `LockerEntry` type

### Tests (`server/packages/shared/src/__tests__/locker.test.ts`) — NEW
- 37 tests across 6 suites using Node's built-in test runner (`node:test`)
- Suites: constant value, serialization round-trip, valid entry acceptance, missing field rejection (all 10 fields), wrong type rejection (14 cases), buildLockerEventTags output
- Run with: `node --import tsx/esm --test server/packages/shared/src/__tests__/locker.test.ts`

## Key Design Decisions

- **Kind 30078 (NIP-78):** Application-specific data kind — avoids collision with standard Nostr kinds. Parameterized replaceable via `d` tag so updating a file replaces the old event.
- **`t` tags for user tags:** Enables relay-side filtering by tag via `#t` filter, so clients can query entries by folder/category without downloading and decrypting everything.
- **Strict validation:** UUID format for id, hex length checks for sha256 (64) and infoHash (40), magnet: prefix, safe integer checks. This prevents malformed entries from propagating.
- **No BigInt:** Size is in the JSON payload (not Prisma), so regular `number` with `Number.isSafeInteger()` is sufficient (safe up to ~9 PB).
