## Key decisions made during implementation

- **Separate ReviewSection components for web and client.** Although the logic is identical, the styling patterns differ: web uses CSS variables (`var(--bg-secondary)`, etc.) while the client uses hardcoded color values in a styles object with `as React.CSSProperties`. Sharing a component would require abstracting the styling system, which is over-engineering for this task.

- **Silent failure on review fetch.** If the reviews API call fails (e.g., game has no reviews endpoint yet, network error), the component silently catches and shows the empty state. Reviews are non-critical — they should never block the game detail page.

- **Component hidden until initial load completes.** The ReviewSection returns `null` until the first fetch resolves, avoiding a flash of "No reviews yet" before data loads.

- **Unicode stars.** Using `\u2605` (filled) and `\u2606` (empty) for star display. No dependencies added.

## How it works

### ReviewSection component
1. Takes a `slug` prop (the game slug)
2. On mount, fetches `GET /api/games/:slug/reviews?limit=10&offset=0` via `apiFetch`
3. Displays:
   - Average star rating with visual stars + numeric value (e.g., "★★★★☆ 4.2")
   - Review count (e.g., "(15 reviews)")
   - Individual review cards with: truncated pubkey (first 8 + last 4 chars), star rating, title, body, formatted timestamp
   - "Load More Reviews" button when more reviews exist beyond current page
4. Empty state: shows "No reviews yet." when `reviewCount === 0`

### Pubkey truncation
`truncatePubkey("abc123456789...xyz")` → `"abc12345...xyz9"`

### Pagination
- Starts at offset 0, limit 10
- "Load More" increments offset by 10 and appends new reviews to existing list
- Button hidden when all reviews loaded (`offset + reviews.length >= reviewCount`)
