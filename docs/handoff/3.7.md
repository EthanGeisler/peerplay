# Sub-task 3.7 — Electron Client: Relay Connection Manager

## What was built
- **`client/src/main/relayManager.ts`** (NEW) — WebSocket relay connection manager with auto-reconnect
- **`client/src/main/index.ts`** (MODIFIED) — Added relay IPC handlers + `relayManager.setMainWindow()`
- **`client/src/main/preload.ts`** (MODIFIED) — Exposed relay channels under `window.boilerdeck.relay`
- **`client/src/renderer/env.d.ts`** (MODIFIED) — Matching type declarations for relay bridge
- **`client/package.json`** (MODIFIED) — Added `ws` and `@types/ws` dependencies

## Key decisions made during implementation
- **Module-level state, not class.** Follows the same pattern as `torrentManager.ts` — module-level variables with exported functions. Simple and consistent with the codebase.
- **Subscriptions survive reconnects.** Active subscriptions are stored in a module-level Map and re-sent when the connection is restored. This means UI subscriptions persist through network interruptions.
- **Events forwarded via IPC `send`, not `invoke`.** Server-pushed events (EVENT, EOSE, OK, NOTICE) are sent as one-way messages to the renderer via `mainWindow.webContents.send()`. The renderer registers listeners via `ipcRenderer.on()`.
- **`relay:status` IPC channel added.** Not in the original spec but useful for the renderer to check connection state without managing its own.

## How it works

### IPC Channels (invoke — request/response)
| Channel | Args | Returns |
|---------|------|---------|
| `relay:connect` | `url: string` | `{ success, error? }` |
| `relay:disconnect` | none | `{ success }` |
| `relay:subscribe` | `subId, filters[]` | `{ success, error? }` |
| `relay:unsubscribe` | `subId` | `{ success }` |
| `relay:publish` | `event` (RelayEvent) | `{ success, error? }` |
| `relay:status` | none | `{ connected, url, subscriptionCount }` |

### IPC Events (one-way, server → renderer)
| Event | Data |
|-------|------|
| `relay:on-event` | `{ subId, event }` |
| `relay:on-eose` | `{ subId }` |
| `relay:on-ok` | `{ eventId, success, message }` |
| `relay:on-notice` | `{ message }` |

### Auto-reconnect
- Exponential backoff: 1s, 2s, 4s, 8s, 16s, 30s (capped)
- Reset to 0 on successful connection
- Disabled when `disconnect()` is called intentionally
- All active subscriptions re-sent on reconnect

### Preload bridge
```typescript
window.boilerdeck.relay.connect("wss://boilerdeck.com/relay")
window.boilerdeck.relay.subscribe("games", [{ kinds: [30001] }])
window.boilerdeck.relay.onEvent((data) => console.log(data.event))
window.boilerdeck.relay.removeListeners()
```

## Gotchas and surprises
- The `ws` module needed to be added to `client/package.json` explicitly. It was available in root `node_modules` (hoisted from server) but the client should own its dependency.
- The client main tsconfig uses `"module": "Node16"` with `"moduleResolution": "Node16"`, so `.js` extensions in imports are required.

## What the next sub-task needs to know
- The relay manager is available but not auto-connected on startup. The renderer (or a future initialization step) needs to call `relay:connect` with the relay URL.
- Sub-task 3.8/3.9 (federation) are server-side — no changes to the client relay manager needed.
- The `relay:on-event` IPC event pushes full event objects to the renderer. Future UI features (reviews, profiles) will subscribe and listen for specific kinds.
