# Sub-task 2.11 — Frontend types and API updates

## What was built
- **`web/src/types.ts`** (MODIFIED) — Added `eventId`, `pubkey`, `custodyMode`, and `NostrEvent` type
- **`client/src/renderer/types.ts`** (MODIFIED) — Matching changes

## Changes

### ApiUser
- `pubkey?: string | null` — Nostr public key (hex)
- `custodyMode?: string` — "CUSTODIAL" or "SELF_CUSTODY"

### ApiGame
- `eventId?: string | null` — linked NIP-01 event ID

### ApiGameDetail
- `pubkey?: string | null` — developer's Nostr public key

### NostrEvent (new)
```typescript
export interface NostrEvent {
  id: string;
  pubkey: string;
  created_at: number;
  kind: number;
  tags: string[][];
  content: string;
  sig: string;
}
```

## Key decisions
- **All fields optional and nullable.** Ensures backwards compatibility — old games/users without events or pubkeys don't break the frontend.
- **Named `NostrEvent` not `Event`.** Avoids collision with the DOM `Event` type.
- **Both `nostrPubkey` and `pubkey` on ApiUser.** The `nostrPubkey` field was already there from Phase 1. The new `pubkey` field matches the server's response shape (2.10). Both are kept for compatibility.
