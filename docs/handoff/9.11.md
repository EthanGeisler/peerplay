# 9.11 — End-to-End Encryption Verification

## Summary

Security audit of all locker encryption code paths, integration tests verifying NIP-44 encryption guarantees, comprehensive security documentation, and UI encryption indicators for both desktop and web clients.

## What Changed

### 1. Encryption Integration Tests: `server/packages/locker/src/__tests__/encryption.test.ts`

11 pure cryptographic tests using Node's built-in `node:test` runner (no extra dependencies). All tests pass.

**Tests:**
1. Encrypted content is base64 NIP-44 ciphertext, not plaintext JSON
2. User A's key can decrypt content encrypted to user A (self-encryption round-trip)
3. User B's key cannot decrypt content encrypted to user A
4. Share: sender re-encrypts to recipient, recipient decrypts successfully
5. Shared copy: sender cannot decrypt the copy encrypted to recipient
6. Tampered ciphertext causes decryption failure
7. Event has correct kind (30078) and d-tag structure
8. Conversation key is deterministic for same key pair
9. Conversation key differs for different recipients
10. Each encryption produces different ciphertext (randomized nonce)
11. Empty plaintext is rejected

Run with: `npx tsx --test server/packages/locker/src/__tests__/encryption.test.ts`

### 2. Security Documentation: `docs/locker-security.md`

Comprehensive security document covering:

- **What the server can see** (all users): file bytes, sizes, pubkey, timestamps, info hash, file count
- **What the server cannot see** (self-custody): filenames, tags, MIME types, SHA-256, magnet URIs
- **Threat model**: compromised server, compromised relay, network observer, honest-but-curious operator
- **Important caveat**: VPS has raw file bytes (seeds torrents). Encryption protects *metadata*, not file content.
- **Implementation details**: NIP-44 v2 spec, self-encryption mechanics, sharing mechanics, code locations
- **Audit findings** for both custodial and self-custody paths
- **Gaps identified**: cleartext `t` tags on events, filename in HTTP upload Content-Disposition
- **Recommendations**: self-custody for max privacy, future client-side file encryption

### 3. UI Encryption Indicators

**Desktop client** (`LockerFileCard.tsx`):
- New `EncryptionBadge` component with `[E]` prefix
- Green badge for self-custody: "End-to-end encrypted" with tooltip explaining local key protection
- Yellow badge for custodial: "Server-managed encryption" with tooltip suggesting self-custody
- `isSelfCustody` prop passed from `LockerPage.tsx` which detects mode via `window.boilerdeck.crypto.hasKey()`
- Appears in both grid and list views

**Web storefront** (`web/src/pages/LockerPage.tsx`):
- `EncryptionBadge` component always shows yellow: "Server-managed encryption" (web is always custodial)
- Tooltip explains the limitation and recommends desktop app with self-custody
- Appears in both `FileRow` (list) and `FileCard` (grid) components

### 4. Code Audit Findings

**Custodial path — correct by design:**
- Server accesses private key only via `getUserPrivkeyHex()` which explicitly rejects `SELF_CUSTODY` users
- Keys encrypted at rest in Redis (AES-256-GCM with `SIGNING_CACHE_KEY`)
- Key access scoped to upload, list, delete, share operations only
- No key leakage to logs or error responses

**Self-custody path — verified secure:**
- Torrent created locally via `createTorrentFromFile()` in `lockerManager.ts`
- LockerEntry JSON encrypted locally via `nip44Encrypt()` from `client/src/main/nip44.ts`
- Event signed locally via `keyManager.signEvent()` — private key never leaves the device
- `uploadRawToVps()` sends only raw bytes + `.torrent` with `self_custody=true` flag
- Server receives and stores file but cannot decrypt the Nostr event content

**Gaps noted (documented, not fixed — deliberate trade-offs):**
1. Cleartext `t` tags on Nostr events leak tag names to relay operators (needed for relay-side filtering)
2. Original filename appears in HTTP multipart Content-Disposition during `uploadRawToVps()` (appears in server logs briefly)
3. File content itself is not encrypted (VPS must seed usable torrents)
