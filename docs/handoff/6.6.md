# Sub-task 6.6 — Privacy Settings UI Page

## What was built
- **`client/src/renderer/pages/Settings.tsx`** (MODIFIED) — Added a "Privacy & Network" section to the existing Settings page with mode selector, SOCKS5 fields, traffic routing checkboxes, test connection button, Tor bootstrap progress display, and info box.

## Key decisions

- **Inline styles matching existing patterns.** All new styles follow the same `styles` object convention as the rest of Settings.tsx. No new CSS files or frameworks.

- **Ref guards for listeners and initial load.** `torListenerAttached` and `privacyLoaded` refs prevent double-firing in React StrictMode, matching the existing `listenersAttached` pattern for the updater.

- **Settings save on blur for text fields.** SOCKS5 host/port/username/password fields save on blur (not on every keystroke) to avoid excessive IPC calls. Checkboxes and radio buttons save immediately on change.

- **Tor auto-start/stop on mode switch.** When user selects Tor mode, `window.boilerdeck.tor.start()` is called automatically. When switching away from Tor, `window.boilerdeck.tor.stop()` is called. Bootstrap progress is shown via the `onBootstrapProgress` listener.

- **`routeTorrentTraffic` forced to false in Tor mode.** When switching to Tor, the torrent routing checkbox is unchecked and disabled, with tooltip explaining Tor is too slow for game downloads. This matches the backend enforcement in torrentManager.ts (6.4).

- **Test Connection uses wall-clock latency.** The renderer measures `Date.now()` before and after the IPC call to `privacy:test-connection`, which includes both IPC overhead and actual proxy latency. This is good enough for a UI indicator.

- **Traffic routing checkboxes hidden when mode is "off".** No point showing proxy routing options when no proxy is active.

## How it works

### Mode selector (radio group)
| Mode | Behavior |
|------|----------|
| Off | No proxy. Checkboxes and test button hidden. |
| Tor (built-in) | Auto-starts Tor, shows bootstrap progress bar, enables API routing checkbox, disables torrent routing checkbox with tooltip |
| Custom SOCKS5 | Shows host/port/username/password fields, enables both routing checkboxes |

### Tor status display
- Progress bar (0-100%) with color coding: blue = connecting, green = connected, red = error
- Status text: "Connecting... N%", "Connected", "Error: ...", "Not started"
- Listens for `tor:bootstrap-progress` events; also checks `tor.status()` on mount if Tor mode was previously saved

### Test Connection
- Button visible when mode is not "off"
- Shows "Testing..." with disabled state during test
- On success: green "Connected (Nms)" text
- On failure: red error message text

### Settings persistence
- Loaded once on mount via `privacy.getSettings()`
- Saved via `privacy.saveSettings()` on every change (radio/checkbox immediately, text fields on blur)
- `savePrivacySettings()` helper merges overrides with current state to avoid stale closures
