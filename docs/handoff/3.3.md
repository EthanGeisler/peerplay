# Sub-task 3.3 — Relay Package Skeleton

## What was built
- **`server/packages/relay/package.json`** (NEW) — `@boilerdeck/relay` workspace package, depends on `@boilerdeck/shared` and `@boilerdeck/auth`
- **`server/packages/relay/tsconfig.json`** (NEW) — extends base tsconfig with references to shared and auth
- **`server/packages/relay/src/service.ts`** (NEW) — Wraps shared eventStore + adds `deleteEvent`
- **`server/packages/relay/src/routes.ts`** (NEW) — REST endpoints for events (POST, GET, GET by ID)
- **`server/packages/relay/src/index.ts`** (NEW) — Barrel exports for service, routes, crypto, and types
- **`server/src/index.ts`** (MODIFIED) — Swapped `eventRouter` from shared → `relayRouter` from relay

## Key decisions made during implementation
- **Relay routes replace shared eventRoutes.** The relay `relayRouter` handles the same `/api/events` endpoints that the shared `eventRouter` used to. The import in `server/src/index.ts` was swapped. The shared `eventRouter` export still exists but is no longer mounted.
- **Service delegates to shared.** `storeEvent`, `getEvent`, and `queryEvents` in relay's service.ts are thin wrappers around the shared eventStore. This avoids duplicating storage logic while giving the relay package ownership of the API surface.
- **`deleteEvent` is new.** The shared eventStore only had store/get/query. The relay adds `deleteEvent` for NIP-09 deletion events and admin moderation. It unlinks `Game.eventId` before deleting the event row to avoid FK violations.
- **`deleteMany` instead of `delete`.** Uses `deleteMany` for the event deletion (returns count, never throws on not-found). Returns `"DELETED"` or `"NOT_FOUND"`.

## How it works

### Service exports
```typescript
storeEvent(event: SignedEvent): Promise<StoreResult>     // delegates to shared
getEvent(id: string): Promise<SignedEvent | null>        // delegates to shared
queryEvents(filter?: EventFilter): Promise<SignedEvent[]> // delegates to shared
deleteEvent(id: string): Promise<DeleteResult>           // NEW — unlinks games, deletes event
```

### Routes (mounted at /api)
```
POST /api/events  [authenticated] — submit pre-signed event (pubkey must match user)
GET  /api/events  [public]        — query events (kinds, authors, limit, since, until)
GET  /api/events/:id [public]     — get single event by ID
```

### Route ownership transfer
```typescript
// server/src/index.ts — BEFORE
import { eventRouter } from "@boilerdeck/shared";
app.use("/api", eventRouter);

// server/src/index.ts — AFTER
import { relayRouter } from "@boilerdeck/relay";
app.use("/api", relayRouter);
```

## Gotchas and surprises
- **tsconfig references cause `tsc --noEmit` errors.** The `references` field requires `composite: true` on referenced projects, which shared/auth don't have. This is a pre-existing issue across all packages (auth has the same problem). The references are for IDE navigation only — runtime imports work fine via Node module resolution.
- **Materialization errors are logged, not swallowed.** The review caught a silent `catch {}` — fixed to `console.warn` so broken materialization is visible in production logs.

## What the next sub-task needs to know
- **3.4 (WebSocket relay)** should import types from `@boilerdeck/relay` (`Subscription`, `EventFilter`, `ClientMessage`, `RelayMessage`).
- **3.4 needs to attach to the http.Server.** Currently `server/src/index.ts` uses `app.listen()` which returns an `http.Server`. The WebSocket server needs this reference. Change to: `const server = app.listen(...)` then `attachRelayWebSocket(server)`.
- The relay's `EventFilter` (in types.ts) has `ids`, `#e`, `#p` fields that the shared `queryEvents` doesn't support. 3.4's subscription matching will need custom logic for tag-based filters.
- `deleteEvent` has no REST endpoint yet — it will be used by NIP-09 handling in the WebSocket layer or a future admin endpoint.
