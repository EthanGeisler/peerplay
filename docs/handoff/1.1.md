# Sub-task 1.1 — Add crypto dependencies

## What was built
- **`server/packages/auth/package.json`** — updated dependencies to include the correct Nostr-compatible crypto stack

## Key decisions made during implementation
- **secp256k1, not Ed25519.** Original plan used Ed25519 (`@noble/ed25519`). Grok review caught that Nostr NIP-01 requires secp256k1 Schnorr signatures. Switched before any crypto code was written.
- **`@noble/curves` instead of `@noble/secp256k1`.** The standalone `@noble/secp256k1` package is deprecated — `@noble/curves` is the unified successor that bundles all curves. Access secp256k1 via subpath export.
- **`@scure/bip32` for NIP-06.** Nostr key derivation isn't just "mnemonic → key" — it uses BIP32 HD derivation with path `m/44'/1237'/0'/0/0`. Without this package, keys wouldn't match what any Nostr client derives from the same mnemonic.

## Dependencies added
```json
"@noble/curves": "^2.0.0",

"@scure/bip32": "^2.0.1",

```

## Dependencies removed
```json
"@noble/ed25519": "^3.0.1"
```

## Gotchas and surprises
- **`@scure/bip32` has no v5.** The plan originally specified `^5.0.0` — latest is `2.0.1`. This was corrected.
- **ESM export paths require `.js` suffix.** These packages use Node's `exports` field. The correct import paths are:
  - `import { schnorr } from '@noble/curves/secp256k1.js'` (NOT `@noble/curves/secp256k1`)
  - `import { sha256 } from '@noble/hashes/sha2.js'` (NOT `@noble/hashes/sha256`)
  - `import { HDKey } from '@scure/bip32'` (no suffix needed)
  - `import { generateMnemonic, mnemonicToSeedSync } from '@scure/bip39'` (no suffix needed)
  - `import { hex, bech32 } from '@scure/base'` (no suffix needed)
- **`schnorr` is a property on the secp256k1 export**, not a standalone function. Use `schnorr.sign()` and `schnorr.verify()`.

## How to use / test
```bash
# Verify all imports work
node -e "import('@noble/curves/secp256k1.js').then(m => console.log('schnorr:', typeof m.schnorr))"
node -e "import('@noble/hashes/sha2.js').then(m => console.log('sha256:', typeof m.sha256))"
node -e "import('@scure/bip32').then(m => console.log('HDKey:', typeof m.HDKey))"
node -e "import('@scure/bip39').then(m => console.log('ok'))"
node -e "import('@scure/base').then(m => console.log('ok'))"
```

## What the next sub-task needs to know
- Sub-task 1.2 builds `crypto.ts` using these packages. Use the exact import paths above — the `.js` suffix matters.
- `schnorr.sign(messageHash, privateKey)` takes a 32-byte message hash (SHA-256), not raw message bytes. Hash first with `sha256`.
- `schnorr` produces/verifies 64-byte signatures over 32-byte x-only pubkeys (not 33-byte compressed).
- `HDKey.fromMasterSeed(seed).derive("m/44'/1237'/0'/0/0")` gives you `.privateKey` (32 bytes) and `.publicKey` (33 bytes compressed — you need to drop the prefix byte to get the 32-byte x-only pubkey for Nostr).
