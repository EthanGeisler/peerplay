# Sub-task 2.10 — Add pubkey to public API responses

## What was built
- **`server/packages/auth/src/service.ts`** (MODIFIED) — `getMe()` now returns `pubkey` and `custodyMode`
- **`server/packages/catalog/src/service.ts`** (MODIFIED) — `listPublishedGames()` returns `eventId`, `getGameBySlug()` returns `pubkey` and `eventId`

## Changes

### GET /api/auth/me
Added fields:
- `pubkey: string | null` — user's Nostr public key (hex)
- `custodyMode: "CUSTODIAL" | "SELF_CUSTODY"` — key custody mode

The internal `nostrPubkey` field is explicitly set to `undefined` so it doesn't appear in the response (avoiding leaking internal naming).

### GET /api/games (list)
Added field per game item:
- `eventId: string | null` — ID of the associated NIP-01 event

### GET /api/games/:slug (detail)
Added fields:
- `pubkey: string | null` — developer's Nostr public key
- `eventId: string | null` — ID of the associated NIP-01 event

Developer pubkey is fetched via `developer -> user -> nostrPubkey` relation.

## Key decisions
- **All new fields are nullable.** Pre-migration users have `pubkey: null`, pre-Phase-2 games have `eventId: null`.
- **No encrypted key data exposed.** `encryptedNsec` and `encryptedMnemonic` are never included in any response.
