# Sub-task 6.5 — Tor Binary Bundling and Management

## What was built

- **`client/src/main/preload.ts`** (MODIFIED) — Exposed `window.boilerdeck.tor` namespace with `start()`, `stop()`, `status()`, `onBootstrapProgress(callback)`, `removeBootstrapListener()`.
- **`client/src/renderer/env.d.ts`** (MODIFIED) — Added `tor` namespace type declarations matching preload.

- **`client/resources/tor/`** (NEW) — Directory with `.gitkeep` and `README.md` explaining how to add the Tor Expert Bundle binaries.

## Key decisions

- **SocksPort 9150** — Matches the port already used in `proxyManager.ts` (sub-task 6.2). This is the Tor Browser Bundle convention, not the daemon default of 9050.

- **Port-already-in-use is treated as success.** If something is already listening on 9150 (e.g., Tor Browser or a previous `startTor()` that wasn't cleaned up), we assume Tor is available and return `bootstrapProgress: 100`. This avoids failing when the user has Tor Browser open.

- **Bootstrap progress parsed from stdout.** Tor logs `Bootstrapped N% (phase_name)` lines to stdout. We regex-match these and push `tor:bootstrap-progress` events to the renderer for UI display.

- **60-second bootstrap timeout.** Tor circuits can be slow to establish, especially on first run (needs to download consensus). 60 seconds is generous. If it times out, the promise rejects but the process keeps running in the background.

- **Graceful shutdown with 5-second force-kill fallback.** `stopTor()` sends SIGTERM first, then SIGKILL after 5 seconds if the process hasn't exited.

- **Data directory in `app.getPath("userData")/tor-data/`.** Persistent across app restarts so Tor doesn't need to re-download the consensus every time.

- **Tor binaries NOT committed.** The ~15 MB Tor Expert Bundle is too large for git. `client/resources/tor/` contains only `.gitkeep` and a README. Developers and CI must download the bundle separately.

- **`extraResources` filter excludes `.gitkeep` and `README.md`.** Only actual binaries get packaged into the app.

## How it works

### IPC Channels
| Channel | Direction | Returns |
|---------|-----------|---------|
| `tor:start` | renderer → main | `{ running, bootstrapProgress, socksPort, error? }` |
| `tor:stop` | renderer → main | `{ success: true }` |
| `tor:status` | renderer → main | `{ running, bootstrapProgress, socksPort }` |

### Push Events
| Event | Direction | Payload |
|-------|-----------|---------|
| `tor:bootstrap-progress` | main → renderer | `{ progress: number, summary: string }` |

### Preload Bridge
```typescript
window.boilerdeck.tor.start()
window.boilerdeck.tor.stop()
window.boilerdeck.tor.status()
window.boilerdeck.tor.onBootstrapProgress(callback)
window.boilerdeck.tor.removeBootstrapListener()
```

### Start flow
```
tor:start IPC
  → startTor()
    → Check if already running → return status
    → Check tor.exe exists → throw if not
    → Check port 9150 → if in use, assume success
    → spawn("tor.exe", ["--SocksPort", "9150", "--DataDirectory", "<userData>/tor-data/", "--Log", "notice stdout"])
    → Parse stdout for "Bootstrapped N% (phase)" lines
    → Push tor:bootstrap-progress events to renderer
    → Resolve when 100% reached (or reject after 60s)
```

### Shutdown flow
```
app.on("before-quit")
  → torrentManager.destroyClient()
  → if (torManager.isTorRunning()) torManager.stopTor()
    → SIGTERM → wait up to 5s → SIGKILL if needed
```

## Gotchas and surprises

- **Type declarations in two places.** The `tor` types must stay in sync between `preload.ts` (`declare global`) and `env.d.ts`. Same pattern as every other namespace.

- **Windows process killing.** On Windows, `process.kill()` sends `SIGTERM` equivalent. If Tor doesn't respond, the 5-second fallback sends `SIGKILL`.

- **Pre-existing TS errors.** `proxyManager.ts` has 2 pre-existing type errors (`SocksProxyAgent` missing `Agent` methods). These are from sub-task 6.2 and unrelated to this change.

- **Dev mode path.** In development, `getTorBinaryPath()` looks at `<appPath>/resources/tor/tor.exe` — the same directory structure as the source. Developers need the Tor Expert Bundle files here for local testing.
