# Sub-task 2.8 — REST endpoint for pre-signed events

## What was built
- **`server/packages/shared/src/eventRoutes.ts`** (NEW) — Express router with three endpoints for event management
- **`server/packages/shared/src/index.ts`** (MODIFIED) — Re-exports `eventRouter`
- **`server/src/index.ts`** (MODIFIED) — Mounts event router at `/api`

## Endpoints

### POST /api/events (authenticated)
Accepts a pre-signed NIP-01 event. Validates:
1. Shape (all required fields present with correct types)
2. Content size < 1MB, tags count < 1000
3. Signature verification via `verifyEvent()`
4. Pubkey matches authenticated user's `nostrPubkey` (403 if mismatch)
5. Stores via `storeEvent()` (handles replaceable semantics)

Returns 201 `{ ok: true }` on success.

### GET /api/events (public)
Query events with optional filters:
- `kinds` — comma-separated kind numbers
- `authors` — comma-separated pubkey hex strings
- `limit` — max results (default 100, max 500)
- `since` — minimum `created_at` (Unix timestamp)
- `until` — maximum `created_at` (Unix timestamp)

Returns array of SignedEvent objects.

### GET /api/events/:id (public)
Returns a single event by ID, or 404 if not found.

## Key decisions
- **Placed in shared package** (not a new package) since it uses shared utilities directly and is simple enough. The spec explicitly asked for `shared/src/eventRoutes.ts`.
- **No rate limiting yet.** The verification checks note this as a gap. Should be added before production use.
- **Size validation before signature verification.** Cheaper checks (size, shape) run before expensive crypto verification.
