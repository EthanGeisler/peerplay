# Sub-task 3.1 — Event Schema and Crypto Utilities (relay package)

## What was built
- **`server/packages/relay/src/crypto.ts`** (NEW) — Re-exports event crypto from `@boilerdeck/shared` and key crypto from `@boilerdeck/auth`
- **`server/packages/relay/src/types.ts`** (NEW) — Relay-specific types: `RelayEvent`, `EventFilter`, `Subscription`, and all NIP-01 protocol message types

## Key decisions made during implementation
- **Re-export, don't reimplement.** All crypto functions already exist in shared (events.ts) and auth (crypto.ts). The relay crypto module is a facade that lets relay consumers import from one place without depending on `@boilerdeck/auth` directly.
- **Relay-specific `EventFilter` extends shared's.** The relay filter adds `ids`, `#e`, and `#p` fields needed for NIP-01 subscription filters, while shared's `EventFilter` only had `kinds`, `authors`, `since`, `until`, `limit`.
- **Full NIP-01 message type definitions.** `ClientMessage` (REQ/EVENT/CLOSE) and `RelayMessage` (EVENT/EOSE/OK/NOTICE) are typed as tuples matching the wire format. These are needed for sub-task 3.4 (WebSocket relay).

## How it works

### crypto.ts exports
```typescript
// Event-level (from @boilerdeck/shared)
createEvent, verifyEvent, hashEvent, serializeEvent
// + types: SignedEvent, UnsignedEvent

// Key-level (from @boilerdeck/auth)
generateKeypair, generateMnemonic, mnemonicToKeypair, schnorrSign, schnorrVerify, pubkeyHex
```

### types.ts key types
```typescript
type RelayEvent = SignedEvent;  // Alias for relay context

interface EventFilter {
  ids?: string[]; authors?: string[]; kinds?: number[];
  "#e"?: string[]; "#p"?: string[];
  since?: number; until?: number; limit?: number;
}

interface Subscription { id: string; filters: EventFilter[]; connectionId: string; }

// NIP-01 messages
type ClientMessage = ClientReqMessage | ClientEventMessage | ClientCloseMessage;
type RelayMessage = RelayEventMessage | RelayEoseMessage | RelayOkMessage | RelayNoticeMessage;
```

## What the next sub-task needs to know
- Sub-task 3.4 (WebSocket relay) should import message types from `@boilerdeck/relay` — `ClientMessage`, `RelayMessage`, `Subscription`, `EventFilter`.
- The `EventFilter` in types.ts has `#e` and `#p` tag filters that the shared `queryEvents` doesn't support yet. Sub-task 3.4 will need to implement tag-based filtering for WebSocket subscriptions.
