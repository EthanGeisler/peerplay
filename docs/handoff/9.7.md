# 9.7 — Locker UI (Electron Renderer)

## Summary

Built the full Data Locker UI for the Electron renderer. Includes a Zustand store, page component with grid/list view, toolbar, quota bar, drag-and-drop upload zone, file cards with status badges and context menus, and IPC progress listeners. Added "Locker" nav item and `/locker` route to the app. All types pass (`npx tsc --noEmit`).

## What Changed

### New File: `client/src/renderer/stores/lockerStore.ts`

Zustand store managing all locker state:

**State:**
- `entries` (LockerIndexEntry[]) — merged view of local + remote entries
- `uploadQueue` / `downloadQueue` — in-progress transfer tracking
- `quota` ({ used, max }) — storage usage from server
- `viewMode` ('grid' | 'list'), `searchQuery`, `selectedTags`
- `sortField` ('name' | 'size' | 'date'), `sortDir` ('asc' | 'desc')
- `isLoading`, `error`

**Actions:**
- `fetchEntries()` — calls `locker.getEntries()` + `locker.getLocalEntries()` in parallel, merges results (local entries retain their download status, remote entries fill in metadata)
- `uploadFile(tags?)` / `uploadDirectory(tags?)` — calls IPC upload, re-fetches entries on success
- `downloadEntry(entryId)` — adds to download queue, calls IPC download, updates status on completion/error
- `deleteEntry(entryId)` — calls IPC delete, removes from state, refreshes quota
- `setViewMode`, `setSearchQuery`, `setSelectedTags`, `setSortField`, `setSortDir`
- `refreshQuota()` — re-fetches quota from server
- `updateUploadProgress` / `updateDownloadProgress` — called from IPC listeners
- `handleSyncUpdate(entries)` — replaces entries from sync events
- `clearError()`

**Entry merging logic:** `mergeEntries()` builds a Map keyed by entry ID. Local entries (from `lockerStore.ts` in main process) are the base — they have download status and local paths. Remote entries (from the server API) update metadata fields. New remote entries not found locally get `downloadStatus: 'available'`.

## Key Design Decisions

- **Access token from `getAccessToken()`:** The locker IPC methods require an access token as the first argument. The store imports `getAccessToken` from `api.ts` to get the current token without storing it in Zustand state.

- **Merge strategy for entries:** Remote entries (from server API) provide authoritative metadata. Local entries (from main process locker index) provide download status and local file paths. The merge preserves both, keyed by entry ID.

- **Drag-and-drop triggers file dialog:** In Electron's sandboxed context, we cannot reliably get file paths from browser drag events. Instead, dropping files triggers the same native file picker dialog as the upload button. This is a pragmatic choice that works reliably.

- **Context menu is a positioned div:** Uses `position: fixed` at click coordinates, closes on outside mousedown. This follows the pattern used in other Electron apps and avoids needing a portal.

- **No external icon library:** File type indicators use monospace text labels (`[IMG]`, `[PDF]`, etc.) instead of adding an icon library dependency. Clean and functional.

- **Single-page component structure:** The page component manages all state through the Zustand store. Sub-components are pure presentational, receiving props. This matches the convention documented in CLAUDE.md ("State stays in the page, sub-components receive props").
