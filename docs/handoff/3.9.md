# Sub-task 3.9 — External Relay Federation (Inbound)

## What was built
Inbound federation was implemented alongside outbound in `server/packages/relay/src/federation.ts` (see 3.8 handoff for full details).

## Key decisions made during implementation
- **Broad subscription filter.** Subscribes to all events of kinds 30001, 30002, 31337, 31338 from external relays. Does not filter by specific game slugs yet — accepts all game-related events.
- **Signature verification required.** Events with invalid signatures are rejected and logged.
- **Duplicate handling via storeEvent.** The shared eventStore returns `"DUPLICATE"` for events already in the DB. No error, no duplicate rows.
- **Imported events not re-forwarded.** The `importedEventIds` set ensures events received from federation are never sent back out (loop prevention). `markImported()` is called BEFORE `storeEvent()` to prevent any race condition.

## How it works

### Inbound subscription
On connection to each external relay:
```
["REQ", "federation-inbound", { "kinds": [30001, 30002, 31337, 31338] }]
```

### Inbound event processing
1. Parse message — only process `["EVENT", subId, event]` messages
2. Shape validation (all required NIP-01 fields present)
3. Signature verification via `verifyEvent()` — reject bad sigs
4. Mark event ID as imported (loop prevention)
5. Store event via `storeEvent()` — returns `"DUPLICATE"` if already exists
6. Fan out to local WS subscribers via `fanOutEvent()`

### Duplicate handling
- `storeEvent()` handles replaceable event semantics (same pubkey+kind+dTag = replace if newer)
- Exact duplicate ID → returns `"DUPLICATE"`, no error

### Loop prevention
```
Event from external relay → markImported(id) → store → fan out to local WS
                                                    ↓
                                              federateOutbound() called
                                                    ↓
                                              importedEventIds.has(id) = true → SKIP
```

## How to test
Testing federation requires two relay instances or a public Nostr relay that accepts custom kinds. Without `EXTERNAL_RELAYS` configured, federation is a no-op.
