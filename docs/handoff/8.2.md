# 8.2 — Key Management UI in Client

## What was done

Added an "Identity & Keys" section to the Settings page (`client/src/renderer/pages/Settings.tsx`), positioned between the Account section and the Install Location section.

## UI States

### No key exists
- Explanatory text about generating a cryptographic identity
- "Generate Identity" button (btnPrimary style)
- After clicking: 12-word mnemonic grid (3 columns x 4 rows) with numbered words
- Checkbox: "I have written down my recovery phrase"
- "Continue" button (disabled until checkbox checked)
- After Continue: transitions to "key exists" state

### Key exists
- Public Key row: truncated pubkey (first 8 + "..." + last 8 chars), monospace font
- Status row: "Active" in green (#3fb950)
- "Import Recovery Phrase" button: opens inline text input with Import/Cancel buttons
- Import validates 12-word count before calling `importMnemonic()`
- Info box: "Your recovery phrase was shown when you generated your identity. It cannot be retrieved from this device."

## State variables added

- `hasIdentity` — loaded on mount via `window.boilerdeck.crypto.hasKey()`
- `pubkey` — loaded on mount via `window.boilerdeck.crypto.getPublicKey()`
- `showMnemonic` — true after generate, false after Continue
- `mnemonic` — the 12 words (cleared after Continue)
- `backedUp` — checkbox state
- `showImport` — toggle for import input
- `importInput` — typed mnemonic text
- `importError` — validation error display

## Preload bridge methods used

- `window.boilerdeck.crypto.hasKey()` — check if key exists on mount
- `window.boilerdeck.crypto.getPublicKey()` — load pubkey on mount
- `window.boilerdeck.crypto.generateKeypair()` — generate new identity
- `window.boilerdeck.crypto.importMnemonic(mnemonic)` — import from recovery phrase

## Files changed

- `client/src/renderer/pages/Settings.tsx` — added Identity & Keys section with all UI states
