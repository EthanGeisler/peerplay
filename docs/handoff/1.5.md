# Sub-task 1.5 — Cache signing key on login

## What was built
- **`server/packages/shared/src/config.ts`** — added `SIGNING_CACHE_KEY` (required, 64-char hex = 32 bytes)
- **`server/packages/shared/src/middleware.ts`** — added `pubkey?: string` to `JwtPayload` interface
- **`server/packages/auth/src/service.ts`** — updated `login()` to cache decrypted signing key in Redis; updated `generateAccessToken()` to include `pubkey` in JWT payload

## Key decisions made during implementation
- **Separate cache encryption from user-password encryption.** The `encryptForCache()` function uses raw AES-256-GCM with the server's `SIGNING_CACHE_KEY` (no scrypt derivation needed — the key is already 32 bytes). This is much faster than the scrypt-based encryption used for at-rest storage.
- **Cache format:** `nonce(12B hex):tag(16B hex):ciphertext(hex)` — simpler than the `v1:...` format since there's no password derivation step.
- **Only custodial users get cached.** Self-custody users don't have `encryptedNsec` on the server, so there's nothing to cache. Users with no pubkey yet (pre-migration) also skip caching — 1.6 will handle those.
- **TTL matches refresh token expiry.** Uses the same `JWT_REFRESH_EXPIRES_IN` parsing logic. Cache auto-expires when the session would.

## How it works

### Login flow (custodial user with keypair)
```
POST /api/auth/login { email, password }
  → verify password (bcrypt)
  → if user.encryptedNsec && custodyMode == CUSTODIAL:
      → decryptPrivateKey(encryptedNsec, password) → 32-byte privkey
      → encryptForCache(privkey, SIGNING_CACHE_KEY) → "nonce:tag:ciphertext"
      → redis.set("signing_key:{userId}", cached, "EX", refreshTtlSeconds)
  → generateAccessToken() now includes pubkey in JWT payload
  → return { user: { ...existing, nostrPubkey }, accessToken, refreshToken }
```

### JWT payload change
```ts
// Before: { sub, email, role, iat, exp }
// After:  { sub, email, role, pubkey?, iat, exp }
```
`pubkey` is only included if the user has a `nostrPubkey` set.

### Config
```
SIGNING_CACHE_KEY=<64-char hex string>  # Required, 32 bytes
```

## Gotchas and surprises
- **`SIGNING_CACHE_KEY` is required.** Server will fail to start without it in `.env`. Already added to both local and VPS environments.
- **`refresh()` automatically gets pubkey in JWT** because `stored.user` from Prisma includes `nostrPubkey` and `generateAccessToken` now conditionally includes it.
- **No cache on registration.** Registration doesn't cache the signing key — the user will get it cached on their first login. This keeps registration simple and avoids the double-scrypt cost of decrypting what we just encrypted.

## How to test
```bash
# Login with a custodial user
curl -s -X POST https://boilerdeck.com/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"verify14a@example.com","password":"testpass123"}'

# Check Redis for signing_key:<userId>
ssh root@204.168.133.38 "redis-cli GET signing_key:<userId>"
ssh root@204.168.133.38 "redis-cli TTL signing_key:<userId>"

# Decode JWT to check pubkey claim
echo '<accessToken>' | cut -d. -f2 | base64 -d 2>/dev/null | jq .
```
