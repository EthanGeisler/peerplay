# 9.13 — Testing, Polish & Documentation

## Summary

Final phase of the Data Locker. Added integration tests, validation tests, and quota math tests. Implemented keyboard shortcuts and batch operations in the desktop client. Updated all project documentation.

## What Changed

### 1. Integration Tests: `server/packages/locker/src/__tests__/integration.test.ts` (NEW)

Tests locker service functions directly using real NIP-44 encryption (no mocks for crypto):

- **Upload flow**: Create LockerEntry, validate it, encrypt with NIP-44, build kind 30078 event tags, verify d-tag, verify content is encrypted, decrypt and verify round-trip
- **List flow**: Encrypt multiple entries, decrypt all, verify metadata matches. Tests wrong-key rejection (key epoch change)
- **Delete flow**: Verify NIP-09 deletion event structure (kind 5, e-tag reference). Verify d-tag matching for finding entries
- **Quota enforcement**: BigInt math for quota checks — over quota rejected, within quota allowed, exact boundary allowed, 1 byte over rejected
- **Deduplication**: Same SHA-256 shares infoHash, different SHA-256 has independent infoHash
- **Share flow**: Sender encrypts to recipient, recipient decrypts, sender cannot decrypt shared copy. Verify share event tags (p-tag, shared-from, shared-entry). Third party cannot decrypt. Recipient p-tag filtering works

### 2. Locker Service Tests: `server/packages/locker/src/__tests__/locker-service.test.ts` (NEW)

- **LockerEntry validation**: 25+ test cases covering all fields — UUID format, empty strings, hex format, length checks, integer checks, bounds, missing fields, optional peerHints
- **Serialization**: Round-trip, invalid JSON, invalid structure, valid JSON output
- **Event tags**: d-tag + t-tags construction, empty tags case
- **Quota math**: Increment, decrement, floor at zero, large BigInt values, delete + re-upload scenarios
- **Storage helpers**: Path construction patterns, torrent path pattern, SHA-256 format
- **Constants**: LOCKER_ENTRY_KIND = 30078

### 3. Keyboard Shortcuts (Desktop Client)

Updated `client/src/renderer/pages/LockerPage.tsx`:

| Shortcut | Action |
|----------|--------|
| `Ctrl+U` / `Cmd+U` | Trigger file upload |
| `Delete` | Delete selected entry (single) or open batch delete confirmation (multi) |
| `Enter` | Download or open selected entry |
| `Ctrl+A` / `Cmd+A` | Select all visible entries |
| `Escape` | Clear selection |

Shortcuts are ignored when focus is in input/textarea/select elements. Only active on "My Files" tab.

### 4. Batch Operations

**Selection state** added to `client/src/renderer/stores/lockerStore.ts`:
- `selectedEntryIds: string[]` — tracked in Zustand store
- `selectEntry(id)` — single select (replaces)
- `toggleSelectEntry(id)` — Ctrl+click toggle
- `selectRange(id, allVisibleIds)` — Shift+click range select (merges with existing)
- `selectAll(allVisibleIds)` — Ctrl+A
- `clearSelection()` — deselect all
- `batchDownload()` — download all selected sequentially
- `batchDelete()` — delete all selected, clear selection after

**Multi-select UI** in `LockerPage.tsx`:
- Click to select, Shift+click for range, Ctrl+click to toggle
- Batch action bar appears when 2+ entries selected: "N selected", "Download All", "Delete All", "Clear Selection"
- Batch delete confirmation dialog shows count

**File card selection** in `LockerFileCard.tsx`:
- New props: `isSelected`, `onClick`
- Selected state: border highlight (#e94560) + subtle background tint
