# Sub-task 4.1 — Event Kind Definitions and Validation

## What was built
- **`server/packages/relay/src/kinds.ts`** (NEW) — Defines all supported event kinds with constants and per-kind validation functions
- **`server/packages/relay/src/index.ts`** (MODIFIED) — Added barrel exports for all kinds.ts exports

## Key decisions made during implementation
- **Validator registry pattern.** A `Map<number, validator>` makes it easy to add new kinds and keeps per-kind logic isolated. Unknown kinds pass validation (per NIP-01, relays should accept events with unknown kinds).
- **Validation does NOT verify signatures.** `validateEventKind()` only checks kind-specific rules (required tags, content format). Signature verification is a separate concern handled by `verifyEvent()` from shared. This separation means both ws.ts and REST routes can call them independently.
- **Review rating validation is strict.** Kind 31337 requires `rating` to be an integer between 1 and 5. Float ratings (e.g., 3.5) are rejected. This matches the 4.3 spec which says "rating: 1-5" and the verification check "Submit `rating: 3.5` -> rejected".
- **Reused `EVENT_KIND_REVIEW` and `EVENT_KIND_ATTESTATION` values from shared/events.ts** (31337 and 31338) but defined new constants with shorter names (`KIND_REVIEW`, `KIND_ATTESTATION`) for relay context. The values are identical.

## How it works

### Kind constants
```typescript
KIND_PROFILE = 0       // NIP-01 profile metadata
KIND_TEXT_NOTE = 1     // NIP-01 text note
KIND_FOLLOW_LIST = 3   // NIP-02 follow list
KIND_DELETION = 5      // NIP-09 deletion request
KIND_REACTION = 7      // NIP-25 reaction
KIND_REVIEW = 31337    // BoilerDeck game review (parameterized replaceable)
KIND_ATTESTATION = 31338 // BoilerDeck seeding attestation (parameterized replaceable)
```

### Validation rules per kind
| Kind | Required Tags | Content Format |
|------|--------------|----------------|
| 0 (profile) | none | JSON object (non-empty) |
| 1 (text note) | none | any string |
| 3 (follow list) | `p` tags must have values | any (can be empty) |
| 5 (deletion) | at least one `e` tag | any |
| 7 (reaction) | `e` tag | non-empty string (`+`, `-`, emoji) |
| 31337 (review) | `d` tag (game slug) | JSON with `rating` (int 1-5) |
| 31338 (attestation) | `p` tag + `d` tag | JSON object (non-empty) |

### Key function signatures
```typescript
validateEventKind(event: SignedEvent): ValidationResult
// { valid: true } or { valid: false, error: "descriptive message" }

kindName(kind: number): string
// "profile", "text note", ..., "unknown"

isSupportedKind(kind: number): boolean
// true for known kinds, false otherwise
```

### Import from relay package
```typescript
import { validateEventKind, KIND_REVIEW, KIND_ATTESTATION } from "@boilerdeck/relay";
```

## Gotchas and surprises
- None significant. The implementation was straightforward.

## How to use / test

Call `validateEventKind(event)` before storing any event. Example integration point in ws.ts `handleEvent()`:

```typescript
// After signature verification, before storeEvent:
const kindResult = validateEventKind(event);
if (!kindResult.valid) {
  sendOk(ws, event.id, false, `invalid: ${kindResult.error}`);
  return;
}
```
