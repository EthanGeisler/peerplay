# 8.8 — Relay server: Open-source packaging

## What was done

Created a standalone, self-contained relay server at `relay-server/` that can be run by anyone to participate in the BoilerDeck federation network.

## Files created

- `relay-server/package.json` — Dependencies: express, ws, cors, @noble/curves, @noble/hashes, @prisma/client
- `relay-server/tsconfig.json` — ES2022 + NodeNext module resolution
- `relay-server/prisma/schema.prisma` — Minimal schema with Event and FederatedListing models
- `relay-server/src/index.ts` — Complete relay server:
  - Express REST API (relay info, listings CRUD with Schnorr verification)
  - NIP-01 WebSocket relay (REQ/EVENT/CLOSE with full filter matching and fan-out)
  - Event verification using @noble/curves Schnorr signatures
  - Event storage with parameterized replaceable event support
- `relay-server/Dockerfile` — Multi-stage build (node:22-slim)
- `relay-server/docker-compose.yml` — Relay + PostgreSQL
- `relay-server/.dockerignore` — Excludes node_modules/dist/.env from build context
- `relay-server/.env.example` — Configuration reference
- `relay-server/LICENSE` — MIT
- `relay-server/README.md` — Quick start guide

## Key decisions

- **Self-contained crypto**: Uses @noble/curves and @noble/hashes directly instead of importing from @boilerdeck/shared, so the relay has zero dependency on the main monorepo.
- **No auth/payment/license**: This is metadata + events only. Anyone can submit signed listings and events.
- **Import paths use `.js` suffix**: Required for @noble packages v2 with NodeNext module resolution (exports map uses `./secp256k1.js`, `./sha2.js`, `./utils.js`).
- **Event storage uses upsert**: Parameterized replaceable events (with `d` tag) are handled via the `[pubkey, kind, dTag]` unique constraint. Non-replaceable events use the event ID as the dTag fallback.
