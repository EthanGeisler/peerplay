# 9.6 — Client Locker Download & Sync

## Summary

Added relay subscription for locker events, local JSON-based locker index, enhanced download flow with SHA-256 verification and progress events, background sync with periodic polling, auto-download setting, and locker settings persistence. All types pass (`npx tsc --noEmit`).

## What Changed

### New File: `client/src/main/lockerStore.ts`

JSON file-based local index at `userData/locker-index.json`. Tracks per-entry metadata and download status.

**Types:**
- `DownloadStatus` — `'available' | 'downloading' | 'downloaded' | 'seeding' | 'error'`
- `LockerIndexEntry` — `{ entryId, filename, size, mimeType, sha256, infoHash, magnetUri, tags, downloadStatus, localPath, lastSynced, createdAt, version }`

**Functions:**
- `loadIndex()` — Read index from disk
- `saveIndex(entries)` — Replace entire index
- `upsertEntry(entry)` — Insert or update by entryId
- `removeEntry(entryId)` — Remove from index
- `getEntry(entryId)` — Get single entry or null
- `getEntriesByStatus(status)` — Filter by download status
- `setDownloadStatus(entryId, status, localPath?)` — Update status
- `getAllEntries()` — Get all entries

### New File: `client/src/main/lockerSettings.ts`

JSON file-based settings at `userData/locker-settings.json`.

**Settings:**
- `autoDownload` (boolean, default: false) — Auto-download new entries from sync
- `downloadPath` (string, default: `~/BoilerDeck/Locker/`) — Where to save downloaded files
- `seedAfterDownload` (boolean, default: false) — Keep seeding after download completes

**Functions:**
- `loadSettings()` / `getSettings()` — Load/get settings
- `setAutoDownload(enabled)` — Toggle auto-download
- `setDownloadPath(newPath)` — Change download directory
- `setSeedAfterDownload(enabled)` — Toggle seeding

### Modified: `client/src/main/lockerManager.ts`

#### Relay Sync

- `startLockerSync()` — Opens a dedicated WebSocket to `wss://boilerdeck.com/relay`, subscribes for kind 30078 + kind 5 events authored by the user. On new events: decrypts NIP-44, parses LockerEntry, upserts into local index, notifies renderer via `locker:sync-update`. Reconnects on disconnect with exponential backoff (2s base, 60s max). Polls every 5 minutes by re-subscribing.
- `stopLockerSync()` — Unsubscribes, closes WebSocket, clears timers.
- Uses a separate WebSocket from the main `relayManager` connection to avoid interfering with existing relay subscriptions.

#### Enhanced Download Flow

`downloadEntry(entryId, downloadPath?)` now:
1. Uses settings default path if `downloadPath` not provided
2. Updates local index status to `'downloading'`
3. Sends `locker:download-progress` events every second: `{ entryId, percent, bytesDownloaded, bytesTotal }`
4. After download: verifies SHA-256 against expected hash from local index
5. On SHA-256 mismatch: sets status to `'error'`, rejects with error
6. On success: sets status to `'downloaded'` with `localPath`
7. If `seedAfterDownload` setting is on: keeps torrent client alive, sets status to `'seeding'`
8. On error/timeout: sets status to `'error'`

#### New Exports

- `getLocalEntries()` — Returns all entries from local index (no network)
- `getLockerSettings()` — Returns locker settings
- `setAutoDownload(enabled)` — Toggle auto-download
- `setDownloadPath(newPath)` — Change download directory
- `openFile(filePath)` — Open file in OS default app via `shell.openPath`
- `showInFolder(filePath)` — Show file in OS file explorer via `shell.showItemInFolder`

#### Auto-Download

When `autoDownload` is enabled and a new entry arrives via sync with status `'available'`, `downloadEntry()` is called automatically (non-blocking, errors caught and logged).

## Key Design Decisions

- **Separate WebSocket for sync:** The locker sync uses its own WebSocket connection to the relay, independent of `relayManager`. This avoids interference with existing subscriptions from the renderer (reviews, social feed) and allows the sync to have its own reconnect lifecycle.

- **JSON file index (not SQLite):** Following the plan's recommendation. JSON file is simpler, sufficient for metadata-only storage, and consistent with the existing `store.ts` pattern.

- **SHA-256 verification:** After torrent download completes, the file hash is compared against the expected hash stored in the local index. A mismatch results in an error status and rejection — the file may have been tampered with.

- **Download progress via interval:** Progress events are emitted every 1 second via `setInterval` reading `torrent.progress`, rather than on every data chunk. This limits IPC traffic while still providing responsive progress updates.

- **Auto-download is opt-in:** Defaults to false. When enabled, new entries arriving via sync are automatically downloaded. This matches the plan's decision for on-demand download by default.

- **Settings separate from store:** Locker settings use their own JSON file (`locker-settings.json`) rather than the main config store. This keeps locker-specific settings isolated and avoids polluting the store key whitelist.

- **Seed-after-download keeps torrent client alive:** When enabled, the WebTorrent client is not destroyed after download, allowing the user's device to continue seeding to the swarm. Status is set to `'seeding'`.
