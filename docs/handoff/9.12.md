# 9.12 — Offline & Resilience

## Summary

The locker now works gracefully when devices are offline, the relay is down, or the VPS is unavailable. Includes offline upload queue with exponential backoff, local-first entry loading, multi-relay publish/subscribe, peer-to-peer fallback infrastructure, connection status tracking, graceful degradation UI banners, and a data export feature.

## What Changed

### 1. Offline Upload Queue: `client/src/main/lockerUploadQueue.ts` (NEW)

Persistent queue stored in `userData/locker-upload-queue.json`. When a custodial upload fails due to network error (ECONNREFUSED, ETIMEDOUT, etc.), the file is added to the queue automatically.

- Each item: `{ id, filePath, tags, addedAt, retryCount, lastError, lastRetryAt, permanentlyFailed }`
- Exponential backoff: 1min, 2min, 4min, ... up to 30min max delay
- Max 10 retries before marking as permanently failed
- Queue processing runs every 2 minutes and on app startup
- Verifies file still exists before retry (marks as failed if removed)

### 2. Local-First Locker Index

Enhanced `lockerManager.ts` `getEntries()`:
- Attempts server fetch; on success, updates local index and sets `lastSynced` timestamp
- On network error, returns cached entries from `lockerStore` with a default quota
- Sets `serverOnline` flag for connection status tracking

Enhanced `lockerStore.ts` (main process):
- Added `lastSyncedTimestamp` state with `setLastSynced()` / `getLastSynced()` accessors
- EOSE handler in relay sync also updates `lastSynced`

### 3. Peer-to-Peer Fallback Infrastructure

`server/packages/shared/src/locker.ts`:
- Added optional `peerHints?: string[]` field to `LockerEntry` type
- Updated `validateLockerEntry()` to validate the optional field

`lockerSettings.ts`:
- Added `includePeerHints: boolean` setting (default: `false`)
- Added `setIncludePeerHints()` setter

Self-custody upload in `lockerManager.ts` checks the setting and initializes the `peerHints` array when enabled. Actual IP discovery is a placeholder for future implementation — the infrastructure is ready.

### 4. Multi-Relay Publish & Failover

`lockerSettings.ts`:
- Added `additionalRelays: string[]` setting (default: `[]`)
- Added `setAdditionalRelays()` / `getAdditionalRelays()` accessors

`lockerManager.ts`:
- `publishToAllRelays()`: publishes to primary relay + all additional relays
- `publishToRelay()`: temporary WebSocket publish to a specific relay (10s timeout)
- Self-custody upload now uses `publishToAllRelays()` instead of just the primary relay
- `subscribeOnAdditionalRelay()`: subscribes to locker events on additional relays and processes events the same way as the primary
- `startLockerSync()` now connects to all configured additional relays
- `stopLockerSync()` cleans up all additional relay connections

### 5. Connection Status Tracking

`lockerManager.ts`:
- `serverOnline` flag: set to `true` on successful API calls, `false` on network errors
- `relayConnected` flag: set `true` on WebSocket open, `false` on close
- `getConnectionStatus()`: returns `{ serverOnline, relayConnected, lastSynced, uploadQueueCount }`

### 6. Graceful Degradation UI

`LockerPage.tsx` now shows amber/yellow status banners:
- "Offline -- showing cached entries" when `serverOnline === false`
- "X uploads queued -- will retry when online" when upload queue has items (with Retry Now button)
- "Relay disconnected -- showing cached entries" when relay is not connected
- "Last synced: X minutes ago" timestamp always shown after first sync

Banners are dismissible (x button) but state resets when `fetchConnectionStatus` detects a change. Status polling runs every 30 seconds.

### 7. Data Export

New `exportIndex()` function in `lockerManager.ts`:
- Opens a native save dialog
- Exports all entries from the local locker index as a formatted JSON file
- Includes metadata: entryId, filename, size, mimeType, sha256, infoHash, magnetUri, tags, downloadStatus, localPath
- "Export Index" button added to the toolbar area on LockerPage

### IPC Channels Added

| Channel | Direction | Purpose |
|---------|-----------|---------|
| `locker:get-upload-queue` | invoke | Returns queued uploads |
| `locker:retry-queue` | invoke | Manually trigger queue processing |
| `locker:clear-queue-item` | invoke | Remove a specific item from queue |
| `locker:export-index` | invoke | Export locker index to JSON file |
| `locker:set-additional-relays` | invoke | Configure extra relays |
| `locker:get-connection-status` | invoke | Returns connection/sync status |
