# Sub-task 5.2 — Electron Client: Auto-Generate Attestations After Download

## What was built
- **`client/src/main/attestation.ts`** (NEW) — Module that creates, signs, and publishes kind 31338 attestation events when a torrent download completes. Uses the same Schnorr signing pattern as the review IPC handler.
- **`client/src/main/torrentManager.ts`** (MODIFIED) — Added `developerPubkey` and `startedAt` to `ActiveDownload` metadata. Added `developerPubkey` to `StartDownloadOpts`. Hooked `publishAttestation()` into `torrent.on("done")` handler with try/catch (never blocks download completion).
- **`client/src/main/preload.ts`** (MODIFIED) — Added `developerPubkey?: string` to `startDownload` opts in both the implementation and type declaration.
- **`client/src/renderer/env.d.ts`** (MODIFIED) — Added `developerPubkey?: string` to `startDownload` opts type.
- **`client/src/renderer/stores/downloadStore.ts`** (MODIFIED) — Added `developerPubkey` to download state interface and passes it through to IPC.
- **`client/src/renderer/pages/GameDetail.tsx`** (MODIFIED) — Passes `game.pubkey` (developer's pubkey from API) when starting a download.
- **`client/src/renderer/pages/Library.tsx`** (MODIFIED) — Passes `detail?.pubkey` when starting a download from the library page.

## Key decisions made during implementation

- **Developer pubkey as the `p` tag target.** The attestation's `p` tag references the game developer's pubkey (not a generic VPS seed box pubkey). This makes more sense semantically: the attestation says "I downloaded content published by this creator." The developer pubkey is already available from `GET /api/games/:slug` (added in Phase 2.10).

- **Pubkey threaded through the entire download flow.** The developer pubkey flows: `GameDetail.tsx` (from `ApiGameDetail.pubkey`) -> `downloadStore.startDownload()` -> IPC `downloads:start` -> `torrentManager.startDownload()` -> `ActiveDownload` metadata -> `publishAttestation()` on completion.

- **Best-effort attestation.** Attestation failure never blocks or affects the download flow. The `publishAttestation()` call is wrapped in `.catch()` in torrentManager, and the function itself handles all error cases gracefully (no key, relay not connected, self-attestation).

- **Self-attestation prevention.** If the user's pubkey matches the developer's pubkey (user is downloading their own game), the attestation is silently skipped. This matches the server-side validation in 5.1.

- **Duration tracking.** `startedAt` is recorded when the torrent becomes ready (not when `startDownload` is called), so the duration accurately reflects actual download time, not metadata resolution time.

## How it works

### Attestation flow
1. User starts a download from GameDetail or Library page
2. The developer pubkey (from `ApiGameDetail.pubkey`) is passed through the download flow to the main process
3. `torrentManager.ts` records `startedAt` timestamp when the torrent is ready
4. When `torrent.on("done")` fires:
   - Calculate `durationSeconds = now - startedAt`
   - Get `bytesDownloaded` from `torrent.downloaded || torrent.length`
   - Call `publishAttestation({ infoHash, bytesDownloaded, durationSeconds, developerPubkey })`
5. `attestation.ts`:
   - Gets user's private key (cached relay key or self-custody key)
   - Guards against self-attestation
   - Builds kind 31338 event with `d` tag (infoHash) and `p` tag (developer pubkey)
   - Signs with Schnorr (NIP-01 canonical serialization)
   - Publishes via `relayManager.publish()`

### Attestation event structure
```json
{
  "kind": 31338,
  "content": "{\"infoHash\":\"abc123\",\"bytesDownloaded\":1048576,\"durationSeconds\":120}",
  "tags": [
    ["d", "abc123"],
    ["p", "<developer-pubkey>"]
  ]
}
```

### Key resolution (same as review signing)
1. Try `relayPrivkey`/`relayPubkey` from store (cached from server via `events:cache-relay-keys`)
2. Fall back to `selfCustodyKey` (OS-encrypted via `safeStorage`)
3. If neither available, skip attestation silently

## Gotchas and surprises

- **`torrent.downloaded` vs `torrent.length`.** WebTorrent's `torrent.downloaded` tracks actual bytes received. `torrent.length` is the total torrent size. On completion, `downloaded` should equal `length`, but we use `downloaded || length` as a fallback in case `downloaded` is 0 at the exact moment `done` fires.

- **No developer pubkey = no attestation.** Games uploaded before Phase 2.10 may not have a developer pubkey in the API response. In this case, attestation is silently skipped with a log message.

## How to use / test

### Code-level verification
1. `client/src/main/attestation.ts` exists with `publishAttestation()` function
2. `torrentManager.ts` calls `publishAttestation()` in `torrent.on("done")` handler
3. Attestation content includes `infoHash`, `bytesDownloaded`, `durationSeconds`
4. `p` tag references the developer pubkey

### Runtime verification (requires actual download)
1. Log in to Electron client (so relay keys are cached)
2. Connect to relay
3. Start and complete a download of a game with a developer pubkey
4. Check console for `[attestation] Published attestation for infoHash=...`
5. Query relay for kind 31338 events to verify

## What the next sub-task needs to know
- **5.3 (VPS seed box attestation)** is independent — it publishes attestations from the VPS side. The `p` tag semantics differ: VPS attestations attest that the VPS seeded to a peer, while client attestations attest that the client downloaded from the developer.
- **5.4 (Reputation aggregation)** can query kind 31338 events. Client-generated attestations will have the downloader's pubkey as the event author and the developer's pubkey in the `p` tag.
- The attestation module is a direct function call in the main process, not an IPC handler. It does not need preload bridge exposure since it's only called internally by `torrentManager.ts`.
