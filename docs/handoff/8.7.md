# 8.7 — Client: Multi-relay listing aggregation

## What was done

### 1. Added `relaySource` field to `ApiGame` type
- **File:** `client/src/renderer/types.ts`
- Added `relaySource?: string` to `ApiGame` interface — stores the relay URL a listing was fetched from

### 2. Modified gameStore for multi-relay fetching
- **File:** `client/src/renderer/stores/gameStore.ts`
- Added `relayToHttpUrl()` helper — converts `wss://` relay URLs to `https://` HTTP origins (strips `/relay` path suffix)
- Added `fetchFromRelay()` function — fetches `GET <httpUrl>/api/relay/listings?limit=100` from a single relay, maps response to `ApiGame[]` with `relaySource` set
- Added `sovereignMode: boolean` to store state and `checkSovereignMode()` action
- Modified `fetchGames()` to check sovereign mode:
  - **Sovereign OFF:** uses existing gateway `apiFetch` (no change)
  - **Sovereign ON:** gets relay list via `window.boilerdeck.relays.list()`, fetches from all enabled relays in parallel via `Promise.allSettled`, deduplicates by slug (prefers `wss://boilerdeck.com/relay` version), sorts by title
  - Falls back to gateway if no relays are enabled or if `window.boilerdeck` APIs are unavailable (web storefront)

### 3. Added relay source badge to Store page
- **File:** `client/src/renderer/pages/Store.tsx`
- When sovereign mode is on and a listing has `relaySource`, shows a small pill badge below the studio name with the relay hostname
- Style: `#0f3460` background, `#888` text, 10px font, rounded pill

### 4. Signature verification note
- Signature verification for federated listings is NOT done in the renderer
- This is intentional: importing `@noble/curves` in the browser bundle would add unnecessary weight
- Signatures are already verified server-side during federation import (8.5)
- The client trusts the gateway relay's data, which has already been validated

## Key implementation details

- **Dedup key:** `slug` — same slug from multiple relays shows once, preferring the default relay (`wss://boilerdeck.com/relay`)
- **Relay HTTP conversion:** `wss://example.com/relay` -> `https://example.com` (protocol swap + strip `/relay` path)
- **Relay listings endpoint:** `GET /api/relay/listings` returns `{ listings: [...], total: number }` (from 8.3)
- **Graceful degradation:** If `window.boilerdeck.sovereignty` or `window.boilerdeck.relays` don't exist (web storefront), falls back to gateway-only mode
- **Error handling:** Individual relay fetch failures are silently ignored (`Promise.allSettled`) — partial results from working relays still display
