# Sub-task 1.8 — Key export and custody switch

## What was built
- **`server/packages/auth/src/service.ts`** — added `exportKeys()` and `switchCustody()` functions
- **`server/packages/auth/src/routes.ts`** — added `POST /api/auth/export-keys` and `POST /api/auth/switch-custody` (both authenticated)
- **`server/packages/auth/src/schemas.ts`** — added `exportKeysSchema` and `switchCustodySchema`

## Key decisions made during implementation
- **Export returns both hex and bech32 formats.** Users get `privateKey` (hex) + `nsec` (bech32) and `pubkey` (hex) + `npub` (bech32). This covers both programmatic use and Nostr client import.
- **Switch-custody is one-way and explicit.** Requires `mode: "SELF_CUSTODY"` in the request body (not just a toggle). Response includes both `message` and `warning` fields to make the irreversibility clear.
- **Password required for both operations.** Defense in depth — a stolen JWT can't export keys or switch custody without knowing the password.

## How it works

### Export keys
```
POST /api/auth/export-keys  [Authorization: Bearer <token>]
  { password }
  → verify password (bcrypt)
  → if self-custody → 400 (no keys to export)
  → decryptPrivateKey(encryptedNsec, password) → 32-byte privkey
  → return { privateKey (hex), nsec (bech32), pubkey (hex), npub (bech32) }
```

### Switch custody
```
POST /api/auth/switch-custody  [Authorization: Bearer <token>]
  { mode: "SELF_CUSTODY", password }
  → verify password (bcrypt)
  → if already self-custody → 400
  → db.user.update: encryptedNsec=null, encryptedMnemonic=null, custodyMode=SELF_CUSTODY
  → redis.del("signing_key:{userId}")
  → return { message, warning }
```

## Gotchas and surprises
- **Switch custody doesn't invalidate the JWT.** The current JWT still has `pubkey` in it, which is fine — the pubkey doesn't change, only the custody mode. The user's identity is preserved.
- **After switch, `recover-mnemonic` and `export-keys` both return errors.** The encrypted data is gone — these endpoints check custody mode first.

## What the next sub-task needs to know
- Users can now fully export their identity and go self-custody
- After switching, the only way to authenticate is challenge-based login (1.7) or email/password
- The signing key cache is cleared on switch — Phase 2 event signing for switched users will need the client to sign locally
