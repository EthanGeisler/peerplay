# Sub-task 6.7 — Gateway .onion Endpoint Documentation

## What was built

1. **`ONION_ADDRESS` config option** — Added to server config schema (`server/packages/shared/src/config.ts`) as an optional string field. No server behavioral changes; it's purely a config field exposed via relay info.

2. **Relay info includes onion address** — Updated `buildRelayInfo()` in `server/packages/relay/src/routes.ts` to include `onion_address` in the response when `ONION_ADDRESS` is configured. Both `/api/relay/info` and NIP-11 `GET /relay` endpoints return it.

3. **Client auto-switch to .onion in Tor mode** — Added `.onion` auto-discovery to `client/src/renderer/api.ts`:
   - When Tor mode is active and API routing is enabled, the client fetches relay info (via the SOCKS5 proxy) to check for `onion_address`
   - If found, rewrites the API base URL from `https://boilerdeck.com/api` to `http://<onion_address>/api`
   - Discovery runs once per session (cached in module-level variables)
   - Resets when switching away from Tor mode
   - Best-effort: failures silently fall back to clearnet URL through Tor
   - Both `proxiedApiFetch` and `fetchTorrentFileBase64` use the effective base URL

4. **`docs/privacy.md`** — Comprehensive privacy documentation covering:
   - How each privacy mode works (Off / Tor / SOCKS5)
   - Privacy guarantees and limitations for each mode
   - Summary table of what's visible in each mode
   - Step-by-step guide for server operators to set up a Tor hidden service
   - The `.onion` auto-discovery mechanism
   - Known limitations (torrent traffic, WebSocket connections, tracker announces, bridges, DNS, first-party data)

## Key decisions

- **Discovery via relay info, not hardcoded.** The client discovers the `.onion` address dynamically from `/api/relay/info`, so it works for any BoilerDeck instance, not just the official one.

- **Module-level caching with reset.** `_onionApiBase` and `_onionDiscoveryDone` are module-level variables. Discovery runs once per Tor session. Switching away from Tor resets the cache so re-enabling Tor triggers fresh discovery.

- **HTTP for .onion, not HTTPS.** Onion services provide their own end-to-end encryption. Using `http://` avoids certificate issues (you'd need a cert for a `.onion` domain, which is non-trivial). This is standard practice for Tor hidden services.

- **`fetchTorrentFileBase64` also uses effective base.** Even though torrents themselves aren't routed through Tor, the `.torrent` file metadata request is an API call and benefits from onion routing.
