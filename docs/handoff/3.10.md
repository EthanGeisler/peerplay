# Sub-task 3.10 — Relay Discovery Endpoint

## What was built
- **`server/packages/relay/src/routes.ts`** (MODIFIED) — Added `GET /api/relay/info` and NIP-11 `GET /relay` handler
- **`server/packages/relay/src/index.ts`** (MODIFIED) — Exports `nip11Router`
- **`server/src/index.ts`** (MODIFIED) — Mounts `nip11Router` at root level (not under /api)

## Key decisions made during implementation
- **Separate `nip11Router` for /relay path.** The NIP-11 spec requires that `GET /relay` with `Accept: application/nostr+json` returns the info document (not a WebSocket upgrade). Since the relay router is mounted under `/api`, a separate router handles the root-level `/relay` path.
- **Shared `buildRelayInfo()` helper.** Both `/api/relay/info` and the NIP-11 handler return the same info document. The helper function builds it once.
- **NIP-11 falls through if no nostr+json Accept header.** The handler calls `next()` for non-NIP-11 requests, allowing the WebSocket server to handle the upgrade.

## How it works

### GET /api/relay/info (REST)
Returns the relay info document as JSON:
```json
{
  "name": "BoilerDeck Relay",
  "description": "Nostr-compatible relay for the BoilerDeck decentralized game distribution platform",
  "relay_url": "wss://boilerdeck.com/relay",
  "supported_nips": [1, 11],
  "software": "boilerdeck-relay",
  "version": "0.1.0",
  "limitation": {
    "max_message_length": 1048576,
    "max_subscriptions": 20,
    "max_filters": 10,
    "max_event_tags": 1000
  },
  "external_relays": ["wss://..."]
}
```

### NIP-11: GET /relay with Accept header
```bash
curl -H "Accept: application/nostr+json" https://boilerdeck.com/relay
```
Returns the same document with `Content-Type: application/nostr+json`.

### Routing
1. Express middleware mounts `nip11Router` BEFORE the error handler
2. `nip11Router` handles `GET /relay` — checks Accept header
3. If `Accept` contains `application/nostr+json` → returns info document
4. Otherwise → calls `next()` → WebSocket server handles the upgrade

## Gotchas and surprises
- The NIP-11 handler must be mounted at the root level, not under `/api`. The WebSocket server listens on `/relay` (root path), so the NIP-11 handler must intercept at the same level.
- Express's `next()` properly delegates to the `ws` WebSocket server for upgrade requests.

## How to use / test
```bash
# REST info endpoint
curl -s https://boilerdeck.com/api/relay/info | jq .

# NIP-11 (Accept header)
curl -s -H "Accept: application/nostr+json" https://boilerdeck.com/relay | jq .

# Normal WS connection still works
wscat -c wss://boilerdeck.com/relay
```
