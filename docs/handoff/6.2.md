# Sub-task 6.2 — SOCKS5 Proxy Module for HTTP Traffic

## What was built
- **`client/src/main/proxyManager.ts`** (NEW) — Exports `getProxyAgent(settings)` and `testProxyConnection(settings)`. Uses `socks-proxy-agent` to create SOCKS5 proxy agents for Tor and custom proxy configurations.
- **`client/src/main/index.ts`** (MODIFIED) — `privacy:test-connection` IPC handler now calls `testProxyConnection()` from proxyManager instead of returning a placeholder.
- **`socks-proxy-agent`** added to client dependencies.

## Key decisions

- **`socks5h://` protocol prefix** — The `h` suffix means DNS resolution happens through the proxy, not locally. This is critical for Tor (local DNS would leak the destination hostname).

- **Tor default port is 9150** — This is the Tor Browser Bundle's SOCKS port. Standard Tor daemon uses 9050, but most desktop users will have the browser bundle.

- **`node:https` for test requests** — Not `fetch`, because Electron's `fetch` may not support custom agents in all versions. `https.request` with the proxy agent is reliable.

- **10-second timeout** — Proxy connections (especially Tor) are slower than direct. 10 seconds is generous enough for Tor circuits but won't hang the UI.

- **URL-encode auth credentials** — Username and password are `encodeURIComponent`-encoded in the proxy URL to handle special characters safely.

- **Error-specific messages** — `ECONNREFUSED`, `ENOTFOUND`, `ETIMEDOUT`, and SOCKS5 auth failures each get a human-readable error message.

## How it works

### `getProxyAgent(settings)`
| Mode | Returns |
|------|---------|
| `off` | `undefined` |
| `tor` | `SocksProxyAgent("socks5h://127.0.0.1:9150")` |
| `socks5` | `SocksProxyAgent("socks5h://[user:pass@]host:port")` |

### `testProxyConnection(settings)`
1. Creates a proxy agent from settings
2. Makes an HTTPS GET to `https://boilerdeck.com/api/health` through the proxy
3. Measures latency
4. Returns `{ success: true, latencyMs, ip? }` on HTTP 2xx/3xx
5. Returns `{ success: false, error }` on any failure — never throws

### IPC wiring
`privacy:test-connection` reads the stored privacy settings (or defaults), passes them to `testProxyConnection()`, and returns the result to the renderer.

## What the next sub-task needs to know
- **`getProxyAgent(settings)` is ready to use** — pass it as the `agent` option to any `http.request` / `https.request` call to route traffic through the proxy.
- **The agent can be used with WebTorrent** if the torrent library supports custom HTTP agents for tracker communication (sub-task 6.3+).
- **`routeApiTraffic` and `routeTorrentTraffic` flags are not yet consumed** — they exist in settings but the proxy module doesn't enforce them. Whoever integrates the proxy into API calls and torrent traffic should check these flags.
- **No global proxy patching** — the module returns agents on demand. Each caller decides whether to use the proxy. This avoids side effects and makes it easy to selectively proxy only certain traffic.
