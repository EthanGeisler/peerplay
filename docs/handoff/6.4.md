# Sub-task 6.4 — Route BitTorrent Traffic Through SOCKS5

## What was built
- **`client/src/main/torrentManager.ts`** (MODIFIED) — Reads privacy settings before each download. When mode is `"socks5"` and `routeTorrentTraffic` is `true`, creates a WebTorrent client with DHT, LSD, and UTP disabled, and tracker HTTP announces routed through the SOCKS5 proxy via `bittorrent-tracker`'s `proxyOpts`.

## Key decisions

- **Only SOCKS5 mode, never Tor.** `shouldRouteTorrents()` explicitly checks `mode === "socks5"` — Tor is too slow for multi-GB game downloads. When mode is `"tor"` or `"off"`, torrent behavior is unchanged (direct as before).

- **Client-level privacy, not per-torrent.** DHT, LSD, and UTP are WebTorrent client-level settings, not per-torrent. When privacy config changes and no torrents are in-flight, the client is destroyed and recreated with the correct settings. If torrents are active, the existing client is reused (can't change mid-download).

- **`proxyOpts` flows through the existing stack.** WebTorrent passes `tracker` options → `torrent-discovery` passes them to `bittorrent-tracker` → `bittorrent-tracker` uses `proxyOpts.httpAgent`/`proxyOpts.httpsAgent` for HTTP tracker announces. This was verified by reading the source of all three libraries.

- **UTP disabled in privacy mode.** UTP is a UDP-based transport protocol that leaks the real IP, same as DHT and LSD. Disabling it forces all peer connections over TCP.

- **Tracker proxying covers the most important leak.** The tracker is the single point that sees every peer's IP. By proxying tracker HTTP announces through SOCKS5, the tracker only sees the proxy's IP. This is the highest-value privacy improvement.

## Limitations

- **TCP peer connections are NOT proxied.** WebTorrent does not support SOCKS5 for TCP peer-to-peer connections. Peers you connect to (or who connect to you) will see your real IP. This is a limitation of the WebTorrent library.

- **UDP trackers are not proxied.** Only HTTP/HTTPS tracker announces go through the proxy. UDP tracker announces cannot be proxied through SOCKS5 (UDP association is theoretically possible via `bittorrent-tracker`'s `socksProxy` option, but is unreliable). BoilerDeck's torrents use HTTP trackers, so this is not a practical concern.

- **Web seeds (if present in .torrent) are not proxied.** WebTorrent's web seed connections (HTTP) do not go through the proxy agent. BoilerDeck-generated torrents do not include web seeds, so this is a non-issue in practice.

- **Privacy config change requires no active downloads.** If the user toggles privacy settings while a download is in progress, the change won't take effect until the current download completes and a new one starts.

## How it works

### Privacy check flow
```
startDownload()
  → getPrivacySettings() — reads from JSON store (or returns defaults)
  → shouldRouteTorrents(settings)
    → true only when mode === "socks5" AND routeTorrentTraffic === true
  → getClient(privacyActive)
    → if client exists with different privacy config and no active torrents: destroy + recreate
    → if creating new client with privacy:
       - dht: false (UDP, leaks IP)
       - lsd: false (UDP multicast, leaks IP on LAN)
       - utp: false (UDP transport, leaks IP)
       - tracker.proxyOpts.httpAgent = SocksProxyAgent (routes HTTP tracker announces through SOCKS5)
       - tracker.proxyOpts.httpsAgent = SocksProxyAgent (routes HTTPS tracker announces through SOCKS5)
```

### What's protected vs. what's not
| Traffic type | Proxied? | Notes |
|---|---|---|
| HTTP/HTTPS tracker announces | Yes | Via `proxyOpts` → `SocksProxyAgent` |
| DHT | Disabled | `dht: false` prevents UDP DHT queries |
| LSD (Local Service Discovery) | Disabled | `lsd: false` prevents LAN multicast |
| UTP (uTorrent Transport) | Disabled | `utp: false` prevents UDP peer transport |
| TCP peer connections | No | WebTorrent doesn't support SOCKS5 for peer TCP |
| Web seeds | No | Not proxied, but BoilerDeck torrents don't use them |
