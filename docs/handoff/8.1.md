# 8.1 — Cryptographic identity: Key generation and storage

## What was built

Extracted all crypto/key logic from inline IPC handlers in `index.ts` into a dedicated `keyManager.ts` module. Added three new IPC channels for querying key state from the renderer.

## Key decisions

- **Mnemonic not stored:** `exportMnemonic()` returns `null`. The mnemonic is shown once at generation time. Custodial users can fetch their server-side encrypted mnemonic via API.
- **safeStorage for encryption:** Private keys encrypted with Electron's `safeStorage` (Windows DPAPI / macOS Keychain / Linux Secret Service) — no manual AES/scrypt.
- **Dynamic imports for ESM packages:** All `@noble/*` and `@scure/*` packages loaded via `await import()` because the main process compiles to CJS and these are ESM-only.
- **Review signing fallback order:** `events:sign-and-publish-review` tries cached relay key first (server-managed), then falls back to self-custody key via `keyManager.signEvent()`.

## How it works

### keyManager.ts exports

| Function | Returns | Description |
|----------|---------|-------------|
| `generateKeypair()` | `{ mnemonic, pubkeyHex }` | Generates BIP-39 mnemonic, derives NIP-06 keypair, encrypts privkey |
| `importMnemonic(mnemonic)` | `{ pubkeyHex }` | Validates + imports mnemonic, derives keypair, encrypts privkey |
| `getPublicKey()` | `string \| null` | Decrypts stored key, derives x-only pubkey |
| `signChallenge(challengeHex)` | `{ signature, pubkeyHex }` | Schnorr-signs SHA-256(challenge) |
| `signEvent(content, kind, tags)` | signed event object | Builds + signs NIP-01 event |
| `hasKey()` | `boolean` | Checks if `selfCustodyKey` exists in store |
| `exportMnemonic()` | `null` | Always null (mnemonic not stored) |
| `getPrivateKeyHex()` | `string` | Internal: decrypts stored key (throws if none) |

### New IPC channels

| Channel | Maps to |
|---------|---------|
| `keys:get-public-key` | `keyManager.getPublicKey()` |
| `keys:has-key` | `keyManager.hasKey()` |
| `keys:export-mnemonic` | `keyManager.exportMnemonic()` |

### Preload bridge additions (under `window.boilerdeck.crypto`)

- `getPublicKey()` -> `keys:get-public-key`
- `hasKey()` -> `keys:has-key`
- `exportMnemonic()` -> `keys:export-mnemonic`

## Gotchas

- NIP-06 derivation path is `m/44'/1237'/0'/0/0` — hardcoded in `keyManager.ts` as `NIP06_PATH`
- Public key is x-only (32 bytes) — the 02/03 compressed prefix is stripped via `.slice(1)`
- `getPrivateKeyHex()` is exported (used by `signChallenge` and `signEvent`) but should be treated as internal
- The review handler still has inline crypto for the relay-key path (server-managed keys aren't in safeStorage, they're stored as plaintext hex in the store)
