# 9.2 — NIP-44 Encryption Module

## Summary

Implemented NIP-44 v2 encrypted payloads for self-addressed messages (user encrypts to own pubkey) and cross-user sharing (encrypt to another user's pubkey). Both server-side and client-side modules produce identical, cross-compatible output. Full test coverage with 22 passing tests.

## What Changed

### New Dependency: `@noble/ciphers`
- Installed in `server/packages/auth` and `client/`
- Provides `xchacha20poly1305` for NIP-44's required AEAD cipher

### Server Module: `server/packages/auth/src/nip44.ts` — NEW
- `getConversationKey(senderPrivkey, recipientPubkey)` — ECDH shared secret → HKDF-SHA256 → 32-byte conversation key
- `nip44Encrypt(plaintext, senderPrivkey, recipientPubkey)` — returns base64-encoded NIP-44 v2 payload
- `nip44Decrypt(ciphertext, receiverPrivkey, senderPubkey)` — decrypts and returns UTF-8 plaintext
- Internal helpers: `calcPaddedLength`, `pad`, `unpad`, `bufferToBase64`, `base64ToBuffer`
- Uses synchronous imports (server runs ESM natively)

### Client Module: `client/src/main/nip44.ts` — NEW
- Same three public functions: `getConversationKey`, `nip44Encrypt`, `nip44Decrypt`
- All functions are `async` because Electron main process compiles to CJS and requires dynamic `import()` for ESM-only `@noble/*` packages
- Identical cryptographic logic — produces cross-compatible output with server module

### Tests: `server/packages/auth/src/__tests__/nip44.test.ts` — NEW
- 22 tests across 7 suites using Node's built-in test runner (`node:test`)
- **Round-trip** (4): short message, long message (5000 chars), unicode, JSON locker entry
- **Self-encryption** (2): encrypt/decrypt to own pubkey, deterministic conversation key
- **Cross-user** (3): alice→bob, symmetric conversation key, bob→alice
- **Format** (4): valid base64, version byte 0x02, correct structure, random nonce per encryption
- **Padding** (2): min 32-byte pad for short messages, 33-byte message pads to 64
- **Error handling** (5): invalid version byte, tampered ciphertext, wrong key, empty plaintext, truncated payload
- **Conversation key** (2): 32-byte output, different keypairs produce different keys
- Run with: `node --import tsx/esm --test server/packages/auth/src/__tests__/nip44.test.ts`

## NIP-44 v2 Encryption Flow

1. **ECDH shared secret**: `secp256k1.getSharedSecret(privkey, '02' + pubkey)` → take x-coordinate (bytes 1..33)
2. **HKDF key derivation**: `extract(sha256, sharedX, 'nip44-v2')` → `expand(prk, undefined, 32)` → 32-byte conversation key
3. **Padding**: 2-byte big-endian length prefix + plaintext + zero-padding to next power of 2 (minimum 32 bytes)
4. **Encryption**: `xchacha20poly1305(conversationKey, nonce).encrypt(paddedPlaintext)` → ciphertext + 16-byte MAC
5. **Payload**: `base64(0x02 || nonce[24] || ciphertext_with_mac)`

For self-addressed messages (data locker): sender privkey and recipient pubkey belong to the same user, so the ECDH shared secret is deterministic.

## Key Design Decisions

- **NIP-44 over NIP-04**: NIP-04 uses AES-CBC without padding, leaking message lengths. NIP-44 uses XChaCha20-Poly1305 with power-of-2 padding — proper authenticated encryption with metadata protection.
- **Async client, sync server**: Client uses `async` + dynamic `import()` for ESM-only `@noble/*` packages (Electron CJS main process constraint). Server uses static imports since it runs ESM natively.
- **`hexToBytes` for ECDH inputs**: `@noble/curves` v2 requires `Uint8Array` inputs (not hex strings). Both modules convert hex privkey/pubkey to bytes before calling `getSharedSecret`.
- **Buffer for base64**: Both modules use Node.js `Buffer` for base64 encode/decode. This works in both server (native) and Electron main process (Node.js runtime).
