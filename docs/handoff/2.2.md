# Sub-task 2.2 — Event utility module

## What was built
- **`server/packages/shared/src/events.ts`** (NEW) — NIP-01 compatible event serialization, hashing, signing, and verification
- **`server/packages/shared/src/index.ts`** — re-exports all event functions and types
- **`server/packages/shared/package.json`** — added `@noble/curves` and `@noble/hashes` as explicit dependencies

## Key decisions made during implementation
- **Module lives in shared, not auth.** Both the auth package (2.4: server-side signing) and the future relay package (Phase 3) need these functions. Putting them in auth would create a circular dependency.
- **`verifyEvent` never throws.** All malformed inputs (missing fields, wrong-length hex, non-hex strings, compressed pubkeys, id mismatches) return `false`. This makes it safe to call on untrusted data from federation without try/catch.
- **`createEvent` validates `created_at`.** Rejects negative values and values beyond `Number.MAX_SAFE_INTEGER` to prevent silent precision loss in JSON.stringify.
- **Added `normalizeDTag` helper.** Addresses the PostgreSQL NULL uniqueness footgun discovered during 2.1 verification: `@@unique([pubkey, kind, dTag])` allows multiple NULLs. Replaceable kinds (30000-39999) always get `dTag: ""`, regular kinds get `null`.
- **Private key accepts both hex string and Uint8Array.** Convenience for callers — the signing service (2.4) will have hex from Redis, but test code may have Uint8Array.

## How it works

### Exported functions
- `serializeEvent(event)` → NIP-01 canonical JSON: `[0, pubkey, created_at, kind, tags, content]`
- `hashEvent(event)` → SHA-256 of UTF-8 encoded serialized string → 64-char hex
- `createEvent(params, privateKey)` → computes id (hash), signs with Schnorr, returns full `SignedEvent`
- `verifyEvent(event)` → validates types, lengths, recomputes hash, checks Schnorr sig → boolean
- `extractDTag(tags)` → finds `d` tag value, returns `null` if absent
- `isReplaceableKind(kind)` → `true` for kinds 30000-39999
- `normalizeDTag(kind, tags)` → returns `""` for replaceable kinds (never null), `null` for regular kinds

### Kind constants
- `EVENT_KIND_GAME_LISTING = 30001`
- `EVENT_KIND_GAME_VERSION = 30002`
- `EVENT_KIND_REVIEW = 31337`
- `EVENT_KIND_ATTESTATION = 31338`

### Types
- `UnsignedEvent` — `{ pubkey, created_at, kind, tags, content }`
- `SignedEvent` extends `UnsignedEvent` — adds `{ id, sig }`

## Gotchas and surprises
- **`@noble/curves` and `@noble/hashes` were already hoisted** from the auth package's node_modules, so `npm install --save` showed "up to date" but still added them to `package.json`. Always check the actual `package.json` diff, not just npm's output.
- **`express-rate-limit` was missing on VPS** — pre-existing issue from Phase 1.7, caused server crash after deploy. Fixed by installing it on VPS directly. The root `package.json` had it but hoisting didn't resolve it for the auth package's import on the VPS.
- **TextEncoder for SHA-256 input.** NIP-01 hashing is over raw UTF-8 bytes. Using `new TextEncoder().encode()` rather than `Buffer.from()` to be explicit about encoding, though both produce identical results for valid strings.

## How to use / test
```typescript
import { createEvent, verifyEvent, normalizeDTag } from "@boilerdeck/shared";

// Create a signed event
const event = createEvent(
  { pubkey: "64-char-hex", created_at: Math.floor(Date.now() / 1000), kind: 30001, tags: [["d", "my-game"]], content: '{"title":"My Game"}' },
  privateKeyHexOrBytes
);

// Verify any event
const valid = verifyEvent(event); // true

// Normalize dTag for DB storage
const dTag = normalizeDTag(event.kind, event.tags); // "my-game" for kind 30001
```

## What the next sub-task needs to know
- Sub-task 2.3 (event storage service) should use `verifyEvent()` before storing and `normalizeDTag()` to compute the `dTag` column value.
- Sub-task 2.4 (signing service) should import `createEvent` and pass the decrypted private key from Redis.
- The `SignedEvent` type has `created_at` (underscore, matching NIP-01), but the Prisma `Event` model has `createdAt` (camelCase, mapped to `created_at_unix`). Callers must map between these.
- `verifyEvent` checks `id` matches the recomputed hash AND verifies the Schnorr signature. Both must pass. A forged `id` with a valid signature will fail.
