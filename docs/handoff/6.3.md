# Sub-task 6.3 — Route API Traffic Through Proxy

## What was built
- **`client/src/main/index.ts`** (MODIFIED) — Added `api:proxied-fetch` IPC handler that performs HTTP requests through the SOCKS5 proxy agent when privacy mode is active. Also imported `getProxyAgent` from proxyManager and `node:https`/`node:http` for the transport layer.
- **`client/src/main/preload.ts`** (MODIFIED) — Exposed `window.boilerdeck.api.proxiedFetch` preload bridge. Updated `declare global` type declarations.
- **`client/src/renderer/env.d.ts`** (MODIFIED) — Added `api` namespace with `proxiedFetch` type declaration.
- **`client/src/renderer/api.ts`** (MODIFIED) — `apiFetch` now checks privacy settings via IPC; if `mode !== "off"` and `routeApiTraffic === true`, routes the request through `window.boilerdeck.api.proxiedFetch` (IPC → main process → SOCKS5 proxy). `fetchTorrentFileBase64` also routes through proxy when enabled.

## Key decisions

- **IPC handler reads settings on every call.** No caching — settings can change at any time from the UI. The overhead of one store read per API call is negligible.

- **15-second timeout for proxied requests.** Longer than direct fetch (which has no explicit timeout) because Tor circuits add latency. Shorter than the 10-second test timeout since API requests should be faster than circuit establishment.

- **`node:https`/`node:http` transport, not `fetch`.** Electron's built-in `fetch` doesn't reliably support custom agents across all versions. `https.request` with the SocksProxyAgent is the reliable path.

- **Error shape matches shared apiFetch exactly.** Proxied path throws the same `ApiError(status, message, code)` so callers don't need to know which path was taken.

- **`shouldProxyApi()` is async.** It reads privacy settings from the main process via IPC on each call. If the IPC call fails for any reason, it returns `false` (falls back to direct fetch).

- **`fetchTorrentFileBase64` also proxied.** This function fetches `.torrent` files and has its own auth/retry logic. When proxy is enabled, it routes through the same IPC channel.

## How it works

### IPC Channel
| Channel | Direction | Args | Returns |
|---------|-----------|------|---------|
| `api:proxied-fetch` | renderer → main | `{ url, method, headers, body? }` | `{ status, headers, body }` |

### Request flow (privacy enabled)
```
Renderer apiFetch("/games")
  → shouldProxyApi() → IPC privacy:get-settings → { mode: "tor", routeApiTraffic: true }
  → proxiedApiFetch("/games")
    → IPC api:proxied-fetch { url: "https://boilerdeck.com/api/games", method: "GET", ... }
      → Main process: reads settings → getProxyAgent(settings) → SocksProxyAgent
      → https.request(url, { agent: socksAgent }) → response
    → Parse JSON, handle errors, return data
```

### Request flow (privacy disabled)
```
Renderer apiFetch("/games")
  → shouldProxyApi() → IPC privacy:get-settings → { mode: "off", routeApiTraffic: true }
  → returns false
  → client.apiFetch("/games") → direct fetch() as before
```

## Gotchas and surprises

- **Type declarations in two places.** The `api` types must stay in sync between `preload.ts` (declare global) and `env.d.ts`. Same pattern as the `privacy` namespace from 6.1.

- **Binary responses (torrent files) through proxy.** The IPC handler returns the response body as a UTF-8 string. For binary content (like .torrent files), this goes through `Buffer.concat(chunks).toString("utf-8")` on the main side and `btoa()` on the renderer side. This works for the torrent file use case but would need adjustment for arbitrary binary responses.

- **204 handling in proxied path.** The proxied path checks for 204 before the error check (status < 200 || >= 300 would catch 204 otherwise). Returns `undefined as T` to match shared client behavior.

## What the next sub-task needs to know
- **API traffic routing is complete.** When privacy mode is enabled with `routeApiTraffic: true`, all `apiFetch` calls and torrent file fetches go through the SOCKS5 proxy.
- **Torrent traffic routing (`routeTorrentTraffic`) is NOT yet implemented.** That flag exists in settings but the torrent manager doesn't use the proxy agent yet.
- **No UI for privacy settings yet.** The settings panel (to toggle modes, enter proxy details) is a separate sub-task.
